## 一、多线程概述

**进程**：正在运行的程序，是资源分配的最小单位。
**线程**：进程内的一个执行路径，是 CPU 调度的最小单位。

**并发与并行：**
- **并发**：CPU 快速切换执行多个线程（看起来同时，实际时间片轮转）
- **并行**：多核 CPU 同时执行多个线程

## 二、创建线程的三种方式

### 2.1 继承 Thread 类

```java
class MyThread extends Thread {
    @Override
    public void run() {
        for (int i = 0; i < 100; i++) {
            System.out.println(getName() + " → " + i);
        }
    }
}

public static void main(String[] args) {
    MyThread t1 = new MyThread();
    MyThread t2 = new MyThread();
    t1.start();  // 启动线程（不是 run()！）
    t2.start();
}
```

**常用方法：**
```java
Thread.currentThread()     // 获取当前线程对象
Thread.sleep(1000)         // 休眠 1 秒（毫秒）
thread.getName()           // 获取线程名
thread.setName("线程1")    // 设置线程名
thread.setDaemon(true)     // 设置守护线程
thread.join()              // 等待该线程执行完毕
thread.setPriority(10)     // 设置优先级（1~10，默认5）
```

### 2.2 实现 Runnable 接口（推荐）

```java
class MyRunnable implements Runnable {
    @Override
    public void run() {
        System.out.println("当前线程: " + Thread.currentThread().getName());
    }
}

public static void main(String[] args) {
    MyRunnable mr = new MyRunnable();
    Thread t = new Thread(mr);
    t.start();

    // Lambda 简化
    new Thread(() -> {
        System.out.println("Lambda 线程");
    }).start();
}
```

**为什么推荐 Runnable？**
1. Java 单继承，实现接口不影响继承其他类
2. 解耦：任务代码和线程管理分离
3. 适合多个线程共享数据

### 2.3 实现 Callable 接口（有返回值）

```java
class MyCallable implements Callable<String> {
    @Override
    public String call() throws Exception {
        return "线程执行完毕，返回结果";
    }
}

public static void main(String[] args) throws Exception {
    // 创建 FutureTask（包装 Callable）
    FutureTask<String> ft = new FutureTask<>(new MyCallable());
    // 交给线程执行
    new Thread(ft).start();
    // 获取结果（会阻塞直到线程执行完毕）
    String result = ft.get();
    System.out.println(result);
}
```

**三种方式对比：**

| 方式 | 优点 | 缺点 |
|------|------|------|
| Thread | 简单直接 | 单继承限制 |
| Runnable | 无单继承限制，解耦 | 无返回值 |
| Callable | 有返回值，可抛异常 | 使用稍复杂 |

## 三、线程安全

### 3.1 什么是线程安全？

多个线程同时操作**共享数据**时，由于 CPU 时间片切换导致数据不一致。

```java
// 示例：两个线程各减 10000 次，理论上 count 应为 0
public class UnsafeTest {
    private static int count = 20000;

    public static void main(String[] args) {
        new Thread(() -> {
            for (int i = 0; i < 10000; i++) count--;
        }).start();
        new Thread(() -> {
            for (int i = 0; i < 10000; i++) count--;
        }).start();

        Thread.sleep(1000); // 等线程跑完
        System.out.println(count); // ❌ 大概率不是 0
    }
}
```

### 3.2 synchronized 关键字

**三种用法：**

```java
// 1. 同步代码块（锁对象）
synchronized (lockObj) {
    // 需要同步的代码
}

// 2. 同步方法（锁 this）
public synchronized void method() {
    // 整个方法加锁
}

// 3. 静态同步方法（锁 类.class）
public static synchronized void staticMethod() {
    // 所有实例共享一把锁
}
```

**解决上述问题：**
```java
private static final Object LOCK = new Object();

// 同步代码块方式
synchronized (LOCK) {
    count--;
}
```

### 3.3 Lock 接口

```java
Lock lock = new ReentrantLock();

// 标准用法
lock.lock();    // 加锁
try {
    // 需要保护的代码
    count--;
} finally {
    lock.unlock(); // 一定要解锁！
}
```

**synchronized vs Lock：**

| | synchronized | Lock |
|--|-------------|------|
| 关键字 | 接口 |
| 自动 | 手动 |
| 隐式 | 显式 unlock() |
| 不公平 | 可选公平/不公平 |
| 锁释放 | 异常自动释放 | 需 finally 解锁 |

## 四、死锁

两个线程互相持有对方需要的锁，互相等待。

```java
Object lockA = new Object();
Object lockB = new Object();

// 线程1
new Thread(() -> {
    synchronized (lockA) {
        Thread.sleep(100);
        synchronized (lockB) { // 等线程2释放 lockB
            System.out.println("线程1完成");
        }
    }
}).start();

// 线程2
new Thread(() -> {
    synchronized (lockB) {
        Thread.sleep(100);
        synchronized (lockA) { // 等线程1释放 lockA
            System.out.println("线程2完成");
        }
    }
}).start();
```

**避免死锁：** 所有线程按**相同顺序**获取锁。

## 五、等待唤醒机制

### 5.1 wait() 和 notify()

必须在 `synchronized` 代码块内使用，操作的是**同一个锁对象**。

```java
// 消费者
synchronized (lock) {
    while (condition == false) {
        lock.wait();   // 释放锁，进入等待
    }
    // 消费...
    lock.notify();     // 唤醒一个等待线程
    // lock.notifyAll(); // 唤醒所有等待线程
}
```

### 5.2 生产者-消费者模式

```java
public class ProducerConsumer {
    private static final List<Integer> queue = new ArrayList<>();
    private static final int MAX_SIZE = 5;

    static class Producer extends Thread {
        @Override
        public void run() {
            synchronized (queue) {
                while (queue.size() == MAX_SIZE) {
                    queue.wait();  // 满了等待
                }
                queue.add(1);
                queue.notify();    // 唤醒消费者
            }
        }
    }

    static class Consumer extends Thread {
        @Override
        public void run() {
            synchronized (queue) {
                while (queue.isEmpty()) {
                    queue.wait();  // 空了等待
                }
                queue.remove(0);
                queue.notify();    // 唤醒生产者
            }
        }
    }
}
```

## 六、volatile 关键字

**作用：** 保证变量的**可见性**，禁止指令重排序。

```java
private volatile boolean flag = true;

// 线程1
while (flag) {
    // 循环...
}

// 线程2 修改 flag
flag = false; // 线程1能立即看到（不加 volatile 可能一直死循环）
```

**volatile 不保证原子性！** 如 count++ 仍是线程不安全的。

## 七、Atomic 原子类

`java.util.concurrent.atomic` 包提供 CAS 实现的原子类：

```java
AtomicInteger count = new AtomicInteger(0);

// 等价于 count++（原子操作）
count.incrementAndGet();

// 常用方法
count.get()                   // 获取当前值
count.set(10)                 // 设置值
count.addAndGet(5)            // +5 并返回
count.compareAndSet(10, 20)   // 如果当前=10则设为20（CAS）
```

**CAS（CompareAndSwap）：** 比较并交换，无锁算法。CPU 级别原子操作，比 synchronized 轻量。
- 缺点：ABA 问题（可通过 AtomicStampedReference 解决）
- 自旋消耗 CPU
