## 一、缓冲流

### 1.1 缓冲流概述

缓冲流（Buffered Stream）是对基本字节流/字符流的一层包装，内部维护了一个**缓冲区**，大幅减少与底层操作系统的交互次数，从而提升读写性能。

```
不使用缓冲流：
  程序 → 系统调用 → 磁盘（每次 1 字节，调 n 次）

使用缓冲流：
  程序 → 缓冲区（8KB）→ 系统调用 → 磁盘（缓冲区满了才调一次）
```

| 原始流 | 缓冲流 |
|--------|--------|
| FileInputStream | BufferedInputStream |
| FileOutputStream | BufferedOutputStream |
| FileReader | BufferedReader |
| FileWriter | BufferedWriter |

### 1.2 字节缓冲流 — BufferedInputStream / BufferedOutputStream

**底层原理：** 缓冲区默认大小 **8192 字节（8KB）**。

- `BufferedInputStream`：从磁盘读取数据时，一次读满 8KB 到缓冲区，程序在缓冲区中读取，避免频繁系统调用
- `BufferedOutputStream`：程序写入的数据先存到 8KB 缓冲区，缓冲区满了才一次性 flush 到磁盘

```java
// 创建方式：包装一个底层流
FileInputStream fis = new FileInputStream("src.txt");
BufferedInputStream bis = new BufferedInputStream(fis);

FileOutputStream fos = new FileOutputStream("dest.txt");
BufferedOutputStream bos = new BufferedOutputStream(fos);
```

**读写的两种方式：**

```java
// 方式一：单字节读写——速度有提升（缓冲区减少了系统调用）
BufferedInputStream bis = ...
BufferedOutputStream bos = ...
int b;
while ((b = bis.read()) != -1) {      // 内部从 8KB 缓冲区取
    bos.write(b);                      // 先写入 8KB 缓冲区
}
// 性能：比直接用 FileInputStream 快几个数量级，
//       但不如用字节数组快

// 方式二：字节数组读写——最快的方式
BufferedInputStream bis = ...
BufferedOutputStream bos = ...
byte[] buffer = new byte[8192];
int len;
while ((len = bis.read(buffer)) != -1) {
    bos.write(buffer, 0, len);
}
// 性能：双层缓冲区叠加，速度最快
```

**性能对比总结：**

| 方式 | 速度排名 |
|------|---------|
| 字节缓冲流 + 字节数组 | 🥇 最快 |
| 字节缓冲流 + 单字节 | 🥈 中等 |
| 字节数组 + 非缓冲流 | 🥉 较慢 |
| 单字节 + 非缓冲流 | 💀 最慢 |

### 1.3 字符缓冲流 — BufferedReader / BufferedWriter

**BufferedReader 独有方法：`readLine()`**

```java
BufferedReader br = new BufferedReader(new FileReader("a.txt"));

// readLine()：读一行，不包含换行符，读到末尾返回 null
String line;
while ((line = br.readLine()) != null) {
    System.out.println(line);  // 直接输出一行内容
}
br.close();
```

**BufferedWriter 独有方法：`newLine()`**

```java
BufferedWriter bw = new BufferedWriter(new FileWriter("b.txt"));
bw.write("第一行");
bw.newLine();    // 跨平台换行（Windows → \r\n, Linux → \n）
bw.write("第二行");
bw.newLine();
bw.close();
```

> `newLine()` 会根据当前操作系统自动插入正确的换行符，比手动写 `\n` 更规范。

**字符缓冲流拷贝文本文件：**

```java
public static void copyTextWithBuffer(File src, File dest) throws IOException {
    BufferedReader br = new BufferedReader(new FileReader(src));
    BufferedWriter bw = new BufferedWriter(new FileWriter(dest));

    String line;
    while ((line = br.readLine()) != null) {
        bw.write(line);
        bw.newLine();  // readLine 不读换行符，所以要手动加
    }

    br.close();
    bw.close();
}
```

## 二、转换流

### 2.1 为什么需要转换流

当文件编码与项目编码不一致时，直接使用 FileReader/FileWriter 会导致乱码。

```java
// 假设项目是 UTF-8，要读取一个 GBK 编码的文件
FileReader fr = new FileReader("D:\\gbk.txt");  // ❌ 乱码
// FileReader 底层默认使用项目编码（UTF-8），读 GBK 文件就乱码了
```

**解决方案：** 使用转换流 `InputStreamReader` / `OutputStreamWriter`，显式指定编码。

### 2.2 InputStreamReader — 字节流 → 字符流（指定编码读取）

```java
// 先拿到字节流
FileInputStream fis = new FileInputStream("D:\\gbk.txt");
// 用转换流指定编码：GBK
InputStreamReader isr = new InputStreamReader(fis, "GBK");

char[] buffer = new char[1024];
int len;
while ((len = isr.read(buffer)) != -1) {
    System.out.print(new String(buffer, 0, len));
}
isr.close();

// ✅ 正常输出：中文内容

// 如果再套一层缓冲流：
BufferedReader br = new BufferedReader(new InputStreamReader(fis, "GBK"));
String line;
while ((line = br.readLine()) != null) {
    System.out.println(line);
}
```

### 2.3 OutputStreamWriter — 字符流 → 字节流（指定编码写入）

```java
FileOutputStream fos = new FileOutputStream("D:\\output.txt");
OutputStreamWriter osw = new OutputStreamWriter(fos, "GBK");

osw.write("你好世界");  // 按 GBK 编码写入
osw.close();
```

**转换流的原理：**

```
InputStreamReader：
  字节流（系统/网络） → 指定编码解码 → 字符流（程序使用）

OutputStreamWriter：
  字符流（程序） → 指定编码编码 → 字节流（文件/网络）
```

### 2.4 读取特殊编码文件的完整案例

```java
// GBK 文件 → 用 UTF-8 项目读取
FileInputStream fis = new FileInputStream("D:\\gbk.txt");
InputStreamReader isr = new InputStreamReader(fis, "GBK");  // 指定 GBK

// 套上缓冲流提升性能
BufferedReader br = new BufferedReader(isr);

String line;
while ((line = br.readLine()) != null) {
    System.out.println(line);
}
br.close();

// 写入 GBK 文件
FileOutputStream fos = new FileOutputStream("D:\\gbk_output.txt");
OutputStreamWriter osw = new OutputStreamWriter(fos, "GBK");
BufferedWriter bw = new BufferedWriter(osw);

bw.write("这是一个 GBK 编码的文件");
bw.close();
```

## 三、序列化流

### 3.1 什么是序列化

**序列化：** 把 Java 对象转换成字节序列，保存到文件或网络传输。
**反序列化：** 把字节序列还原成 Java 对象。

```
序列化：    Java 对象 → ObjectOutputStream → 文件/网络
反序列化：  文件/网络 → ObjectInputStream → Java 对象
```

### 3.2 Serializable 接口

要让一个 Java 对象可序列化，必须实现 `Serializable` 接口：

```java
import java.io.Serializable;

public class Student implements Serializable {
    private String name;
    private int age;

    public Student() {}

    public Student(String name, int age) {
        this.name = name;
        this.age = age;
    }

    // getter / setter...

    @Override
    public String toString() {
        return "Student{name='" + name + "', age=" + age + "}";
    }
}
```

> `Serializable` 是**标记接口**，里面没有任何方法。实现它只是告诉 JVM："这个类的对象可以被序列化"。

### 3.3 ObjectOutputStream — 序列化（写对象）

```java
Student stu = new Student("张三", 23);

ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("D:\\stu.txt"));
oos.writeObject(stu);   // 将对象写入文件（不是纯文本，是二进制）
oos.close();
```

### 3.4 ObjectInputStream — 反序列化（读对象）

```java
ObjectInputStream ois = new ObjectInputStream(new FileInputStream("D:\\stu.txt"));
Student stu = (Student) ois.readObject();  // 返回 Object，需要强制转型
ois.close();

System.out.println(stu);  // Student{name='张三', age=23}
```

### 3.5 transient 关键字

当某个字段不想被序列化时（比如密码、敏感信息），用 `transient` 修饰：

```java
public class User implements Serializable {
    private String username;
    private transient String password;  // ⚠️ 这个字段不会参与序列化

    // 反序列化后，password 为 null（引用类型的默认值）
}
```

```java
User user = new User("admin", "123456");
ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("D:\\user.txt"));
oos.writeObject(user);
oos.close();

ObjectInputStream ois = new ObjectInputStream(new FileInputStream("D:\\user.txt"));
User u = (User) ois.readObject();
System.out.println(u.getUsername());  // admin
System.out.println(u.getPassword());  // null（因为被 transient 修饰）
```

### 3.6 serialVersionUID（序列化版本号）

**问题场景：** 先序列化了一个对象，然后修改了类（增加了新字段），再去反序列化会报错：

```
java.io.InvalidClassException: Student; local class incompatible:
  stream classdesc serialVersionUID = 123456789,
  local class serialVersionUID = 987654321
```

JVM 用 `serialVersionUID` 来验证序列化和反序列化的类是否是同一个版本。如果类没有显式声明，JVM 会根据类结构自动生成一个。类结构改变→生成的 UID 改变→反序列化失败。

**解决方案：显式声明 serialVersionUID**

```java
public class Student implements Serializable {
    private static final long serialVersionUID = 1L;  // 显式声明版本号

    // ... 后续随意增删字段，反序列化不会报错
    // （但不建议在真实项目中随意修改，可能会导致数据不一致）
}
```

### 3.7 一次读写多个对象

**方式一：分批写入，然后依次读取**

```java
// 写入多个对象
Student s1 = new Student("张三", 23);
Student s2 = new Student("李四", 24);
Student s3 = new Student("王五", 25);

ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("D:\\students.txt"));
oos.writeObject(s1);
oos.writeObject(s2);
oos.writeObject(s3);
oos.close();

// 读取多个对象（需要知道写了几个，或用异常检测结尾）
ObjectInputStream ois = new ObjectInputStream(new FileInputStream("D:\\students.txt"));
try {
    while (true) {
        Student s = (Student) ois.readObject();
        System.out.println(s);
    }
} catch (EOFException e) {
    // 读到文件末尾，正常结束
}
ois.close();
```

**方式二（推荐）：用集合封装，一次性写入和读取**

```java
// 写入：将多个对象放入 ArrayList，写一个对象
ArrayList<Student> list = new ArrayList<>();
list.add(new Student("张三", 23));
list.add(new Student("李四", 24));
list.add(new Student("王五", 25));

ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("D:\\students.txt"));
oos.writeObject(list);  // 集合本身也是 Serializable 的
oos.close();

// 读取：读出一个 ArrayList
ObjectInputStream ois = new ObjectInputStream(new FileInputStream("D:\\students.txt"));
ArrayList<Student> list2 = (ArrayList<Student>) ois.readObject();
ois.close();

for (Student s : list2) {
    System.out.println(s);
}
```

## 四、字符输出流的底层原理详解

### 4.1 内部缓冲区

`FileWriter`（以及父类 `OutputStreamWriter`）内部维护了一个**字符缓冲区**，默认大小 **8192 字符**（16KB，因为 Java 的 char 占 2 字节）。

```
调用 fw.write("数据")
  ↓
数据写入内存缓冲区（8192 字符）
  ↓
缓冲区满 / 调用 flush() / 调用 close()
  ↓
数据真正写入磁盘文件
```

### 4.2 为什么要有缓冲区

如果没有缓冲区，每写一个字符就要调用一次操作系统 API 写入磁盘——**极其低效**。

```java
// 没有缓冲区的话，for 循环写 10000 个字符就调 10000 次系统调用
for (int i = 0; i < 10000; i++) {
    fw.write('a');
}
// 有缓冲区：写到缓冲区满了再一次性刷到磁盘，只调几次系统调用
```

### 4.3 flush() 和 close() 的区别

| 方法 | 行为 |
|------|------|
| `flush()` | 将缓冲区数据**强制刷入磁盘**，流仍然可用 |
| `close()` | 先调用 `flush()`，然后**关闭流**，流不可再用 |

```java
FileWriter fw = new FileWriter("D:\\a.txt");

fw.write("hello");
// 此时数据在缓冲区，磁盘文件是空的

fw.flush();     // 数据写入磁盘，但流还在
fw.write(" world");
fw.flush();     // 再次写入磁盘

fw.close();     // 关闭流，不能再写
```

### 4.4 什么时候自动 flush

1. **缓冲区满了**（默认 8192 字符）→ 自动 flush
2. **调用 close()** → 先 flush 再关闭
3. **调用 flush()** → 手动触发

**如果不调 close 会怎样？**

```java
FileWriter fw = new FileWriter("D:\\a.txt");
fw.write("hello");
// 没有 close！！！程序结束
// → 缓冲区数据丢失，a.txt 可能是空文件或只写了部分内容
```

> ⚠️ **重要：** 字符流用完一定要调 `close()` 或 `flush()`，否则数据会丢失。

### 4.5 覆盖模式 vs 追加模式

```java
// 覆盖模式（默认）：清空原文件，重新写入
FileWriter fw1 = new FileWriter("D:\\a.txt");
fw1.write("新内容");
fw1.close();
// a.txt 原来的内容被清空，只有"新内容"

// 追加模式：在文件末尾追加内容
FileWriter fw2 = new FileWriter("D:\\a.txt", true);  // 第二个参数 true
fw2.write("这是追加的内容");
fw2.close();
// a.txt 保留原来内容，末尾加上"这是追加的内容"
```

`FileOutputStream` 也是同样的参数：

```java
new FileOutputStream("D:\\a.txt");        // 覆盖
new FileOutputStream("D:\\a.txt", true);  // 追加
```

### 4.6 FileWriter 源码级总结

```
FileWriter
  └─ extends OutputStreamWriter
       └─ 内部持有 StreamEncoder（字符编码器）
            └─ 持有 8KB char[] 缓冲区
                 └─ 持有 FileOutputStream（最终写字节到文件）
```

写入流程：
1. `fw.write(char[])` → 数据写入 StreamEncoder 的 **char 缓冲区**
2. 缓冲区满 → 编码为字节 → `FileOutputStream.write(byte[])` → 写磁盘
3. `fw.flush()` → 强制将缓冲区剩余数据编码并写磁盘
4. `fw.close()` → flush + 关闭底层流

## 五、要点总结

| 分类 | 核心类 | 关键特性 |
|------|--------|---------|
| 字节缓冲流 | BufferedInputStream / BufferedOutputStream | 8KB 缓冲区，减少系统调用 |
| 字符缓冲流 | BufferedReader / BufferedWriter | readLine() / newLine() |
| 转换流 | InputStreamReader / OutputStreamWriter | 指定编码，解决乱码 |
| 序列化流 | ObjectOutputStream / ObjectInputStream | 写对象/读对象 |
| 序列化约束 | Serializable / transient / serialVersionUID | 标记接口 / 排除字段 / 版本控制 |
| 字符输出流原理 | FileWriter 内部 8192 char 缓冲区 | flush 刷新 / close 关闭 |
| 覆盖/追加 | FileWriter(path) / FileWriter(path, true) | 第二个参数控制追加 |
