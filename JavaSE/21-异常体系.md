## 一、异常概述

### 1.1 什么是异常

异常（Exception）就是程序运行过程中出现的不正常情况。Java 将所有异常都封装为对象，通过异常处理机制让程序在出错时还能以可控的方式结束或恢复。

### 1.2 异常体系结构

```
Throwable（根类）
├── Error（错误，无需处理）
│   ├── OutOfMemoryError
│   ├── StackOverflowError
│   └── ...
└── Exception（异常，需要处理）
    ├── RuntimeException（运行时异常/未检查异常）
    │   ├── NullPointerException
    │   ├── ArrayIndexOutOfBoundsException
    │   ├── ArithmeticException
    │   ├── ClassCastException
    │   └── ...
    └── 其他 Exception（编译时异常/检查异常）
        ├── IOException
        ├── FileNotFoundException
        ├── ParseException
        └── ...
```

- **Error**：JVM 层面的严重错误，程序无法处理，比如内存溢出、栈溢出。不要 try-catch。
- **Exception**：程序层面的异常，可以处理。
  - **RuntimeException 及其子类**：运行时异常。编译时**不强制处理**，可以理会也可以不理会。
  - **非 RuntimeException 的 Exception**：编译时异常（Checked Exception）。编译时**必须处理**，要么 throws 抛出去，要么 try-catch 接住。

### 1.3 编译时异常 vs 运行时异常

| 对比项 | 编译时异常（Checked Exception） | 运行时异常（RuntimeException） |
|--------|-------------------------------|------------------------------|
| 编译检查 | 必须处理，否则编译不通过 | 不强制处理，编译能通过 |
| 常见例子 | IOException, ParseException, SQLException | NullPointerException, 数组越界, 算术异常 |
| 代表场景 | 读取文件、解析日期、连接数据库 | 空指针、除数为 0、类型转换错误 |
| 处理方式 | 必须 try-catch 或 throws | 可以处理也可以不处理 |

```java
// 编译时异常 - 不处理编译报错
SimpleDateFormat sdf = new SimpleDateFormat("yyyy-MM-dd");
// ❌ 编译错误：Unhandled exception: java.text.ParseException
// Date date = sdf.parse("2024-01-01");

// ✅ 必须处理
try {
    Date date = sdf.parse("2024-01-01");
} catch (ParseException e) {
    e.printStackTrace();
}

// 运行时异常 - 编译能通过，运行才出事
int[] arr = new int[5];
System.out.println(arr[10]); // 编译通过，运行抛出 ArrayIndexOutOfBoundsException
```

## 二、JVM 默认处理方式与 throws 声明

### 2.1 JVM 默认处理

当程序出现异常且没有被任何代码处理时，JVM 会做两件事：

1. **将异常信息（类型、原因、位置）打印到控制台**
2. **终止当前正在执行的程序**

```java
public class Demo {
    public static void main(String[] args) {
        System.out.println("开始");
        int[] arr = {1, 2, 3};
        System.out.println(arr[5]); // ArrayIndexOutOfBoundsException
        System.out.println("结束");  // 这行不会执行
    }
}
// 输出：
// 开始
// Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 5 out of bounds for length 3
//         at Demo.main(Demo.java:6)
// "结束" 不会打印
```

### 2.2 throws 关键字：声明异常

如果方法内部抛出了一个编译时异常，但方法自己不想处理，可以用 `throws` 关键字在方法签名上**声明**，把异常抛给调用者去处理。

```java
public void readFile() throws IOException {
    // 这个方法可能抛出 IOException，我不处理，叫调用者处理
    FileInputStream fis = new FileInputStream("a.txt");
}

// 谁调用谁处理
public static void main(String[] args) {
    try {
        readFile();
    } catch (IOException e) {
        e.printStackTrace();
    }
}
```

**throws 可以声明多个异常：**

```java
public void method() throws IOException, ParseException {
    // ...
}
```

> **注意：** throws 只是声明，异常最终还是需要被 try-catch 真正处理掉，否则会一路抛到 JVM，程序就终止了。

### 2.3 throw 关键字：手动抛出异常

`throw` 用于**手动抛出一个异常对象**：

```java
public void setAge(int age) {
    if (age < 0 || age > 150) {
        throw new IllegalArgumentException("年龄必须在 0~150 之间");
    }
    this.age = age;
}
```

`throws` 和 `throw` 的区别：

| throws | throw |
|--------|-------|
| 方法签名上声明 | 方法体内使用 |
| 后面跟异常类名（多个用逗号） | 后面跟异常对象 |
| 表示"该方法可能抛出这些异常" | 表示"我主动抛个异常" |

## 三、try-catch 处理异常

### 3.1 基本格式

```java
try {
    // 可能出异常的代码
} catch (异常类型 变量名) {
    // 异常处理代码
}
```

```java
try {
    FileInputStream fis = new FileInputStream("a.txt");
} catch (IOException e) {
    System.out.println("文件没找到，走默认配置");
}
```

### 3.2 多个 catch 捕捉不同异常

一个 try 后面可以跟多个 catch，分别处理不同类型的异常。

**异常变量名可以复用：** JDK 新特性允许在多个 catch 中使用相同的变量名 `e`。

```java
try {
    String s = "abc";
    System.out.println(s.charAt(10));     // StringIndexOutOfBounds
    SimpleDateFormat sdf = new SimpleDateFormat();
    Date date = sdf.parse("abc");         // ParseException
} catch (StringIndexOutOfBoundsException e) {
    System.out.println("字符串索引越界");
} catch (ParseException e) {
    System.out.println("日期格式解析异常");
}
```

**⚠️ 重要：多 catch 的顺序——子类在前，父类在后。**

```java
try {
    // ...
} catch (ArithmeticException e) {        // ✅ 子类在前
    System.out.println("算术异常");
} catch (RuntimeException e) {           // ⚠️ 父类在后
    System.out.println("运行时异常");
} catch (Exception e) {                  // ⚠️ 父类在后
    System.out.println("其他异常");
}
```

如果父类在前，子类异常会被父类 catch 先逮住，子类 catch 永远不会被执行（编译报错）。

### 3.3 JDK7 多异常捕获

JDK7 开始，可以在一个 catch 中同时捕获多种异常，用 `|` 分隔：

```java
try {
    // ...
} catch (IOException | ParseException e) {
    // IOException 和 ParseException 走同一个处理逻辑
    System.out.println("IO 或解析异常");
}
```

## 四、Throwable 成员方法

Throwable 是所有异常和错误的父类，常用的方法：

| 方法 | 说明 |
|------|------|
| `getMessage()` | 返回**异常原因**的描述字符串（简短） |
| `toString()` | 返回异常的**类型 + 原因描述** |
| `printStackTrace()` | 打印异常信息到控制台（类型 + 原因 + 堆栈跟踪），**最常用** |

```java
public class Demo {
    public static void main(String[] args) {
        try {
            int[] arr = {1, 2, 3};
            System.out.println(arr[5]);
        } catch (ArrayIndexOutOfBoundsException e) {
            System.out.println("getMessage: " + e.getMessage());
            // 输出：Index 5 out of bounds for length 3

            System.out.println("toString: " + e.toString());
            // 输出：java.lang.ArrayIndexOutOfBoundsException: Index 5 out of bounds for length 3

            e.printStackTrace();
            // 输出完整堆栈跟踪（最详细，开发期最常用）
        }
    }
}
```

## 五、finally 与 try-catch-finally

### 5.1 finally 的作用

`finally` 中的代码**无论是否出现异常都会执行**，通常用来释放资源（关闭文件流、数据库连接等）。

```java
FileInputStream fis = null;
try {
    fis = new FileInputStream("a.txt");
    // 读取文件...
} catch (IOException e) {
    e.printStackTrace();
} finally {
    // 无论文件读没读到，都要关流
    if (fis != null) {
        try {
            fis.close();
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

**三种情况都会执行 finally：**

1. try 正常执行完毕 → 执行 finally
2. try 抛出异常被 catch 捕获 → 执行 finally
3. 即使 try 或 catch 中有 return → **先执行 finally 再 return**

### 5.2 finally 中 return 的陷阱（强烈不建议）

如果在 finally 中也写了 return，它会覆盖掉 try 或 catch 中的 return 值：

```java
public static int test() {
    try {
        int a = 10 / 0;  // 抛出异常
        return 1;
    } catch (Exception e) {
        return 2;        // catch 中 return 2
    } finally {
        return 3;        // ⚠️ 这个 return 会覆盖上面的，最终返回 3
    }
}

public static void main(String[] args) {
    System.out.println(test());  // 输出：3
}
```

**结论：永远不要在 finally 中写 return。**

### 5.3 JDK7 的 try-with-resources

从 JDK7 开始，实现了 `AutoCloseable` 接口的资源可以自动关闭，不用写 finally：

```java
// 旧写法（JDK7 前）：手动在 finally 中关流
FileInputStream fis = new FileInputStream("a.txt");
try {
    // 读取...
} finally {
    fis.close();
}

// 新写法（JDK7+）：try-with-resources，自动关
try (FileInputStream fis = new FileInputStream("a.txt")) {
    // 读取...
} catch (IOException e) {
    e.printStackTrace();
}
// 不需要 finally，fis 会自动关闭
```

## 六、自定义异常

当 Java 提供的异常类型不足以描述特定的业务问题时，可以自己定义异常。

### 6.1 自定义运行时异常（继承 RuntimeException）

```java
public class AgeOutOfBoundsException extends RuntimeException {
    // 空参构造
    public AgeOutOfBoundsException() {
    }

    // 带原因信息的构造
    public AgeOutOfBoundsException(String message) {
        super(message);
    }
}
```

### 6.2 自定义编译时异常（继承 Exception）

```java
public class FileTooLargeException extends Exception {
    public FileTooLargeException() {
    }

    public FileTooLargeException(String message) {
        super(message);
    }
}
```

### 6.3 实际使用

```java
public class Student {
    private String name;
    private int age;

    public void setAge(int age) {
        if (age < 0 || age > 150) {
            throw new AgeOutOfBoundsException("年龄必须在 0~150 之间，你传入的是：" + age);
        }
        this.age = age;
    }
}

public class Test {
    public static void main(String[] args) {
        Student s = new Student();
        // s.setAge(-5);  // 抛出 AgeOutOfBoundsException: 年龄必须在 0~150 之间，你传入的是：-5

        try {
            s.setAge(-5);
        } catch (AgeOutOfBoundsException e) {
            System.out.println(e.getMessage());
        }
    }
}
```

**自定义异常的惯例：**

1. 提供两个构造方法：空参构造 + 带 message 参数的构造
2. 带 message 的构造调用父类的 `super(message)`，这样可以通过 `getMessage()` 获取异常原因
3. 命名规范：`XxxException`，以 Exception 结尾

## 七、要点总结

| 分类 | 关键字/类 | 说明 |
|------|-----------|------|
| 异常体系 | Throwable → Error / Exception | Error 不处理，Exception 要处理 |
| 异常分类 | RuntimeException / 其他 Exception | 运行时异常不强制处理，编译时异常必须处理 |
| 声明异常 | throws | 方法签名上声明可能抛出的异常 |
| 抛出异常 | throw | 手动抛出异常对象 |
| 捕获异常 | try-catch | 处理异常，可选多个 catch |
| 释放资源 | finally | 无论是否异常都会执行，不要在里面 return |
| 自动关流 | try-with-resources | JDK7+，自动关闭 AutoCloseable 资源 |
| 成员方法 | getMessage / toString / printStackTrace | printStackTrace 最常用 |
| 自定义异常 | 继承 RuntimeException 或 Exception | 提供空参 + 带 message 构造 |
