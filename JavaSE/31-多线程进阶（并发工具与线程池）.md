## 一、线程池

### 1.1 为什么用线程池？

频繁创建/销毁线程开销很大，线程池**复用已有线程**，提高性能。

**优点：**
- 降低资源消耗
- 提高响应速度
- 便于统一管理

### 1.2 Executors 工具类创建线程池

```java
// 1. 固定线程数
ExecutorService pool = Executors.newFixedThreadPool(3);

// 2. 缓存线程池（不限数量，60s 不活跃则回收）
ExecutorService pool2 = Executors.newCachedThreadPool();

// 3. 单线程池
ExecutorService pool3 = Executors.newSingleThreadExecutor();

// 4. 定时任务线程池
ScheduledExecutorService pool4 = Executors.newScheduledThreadPool(2);
```

### 1.3 提交任务

```java
ExecutorService pool = Executors.newFixedThreadPool(3);

// 方式1：execute（Runnable，无返回值）
pool.execute(() -> System.out.println("任务1"));

// 方式2：submit（Callable，有返回值）
Future<String> ft = pool.submit(() -> {
    Thread.sleep(1000);
    return "任务结果";
});
String result = ft.get(); // 阻塞获取结果
```

### 1.4 线程池核心参数

```java
public ThreadPoolExecutor(
    int corePoolSize,      // 核心线程数（常驻）
    int maximumPoolSize,   // 最大线程数
    long keepAliveTime,    // 非核心线程空闲存活时间
    TimeUnit unit,         // 时间单位
    BlockingQueue<Runnable> workQueue, // 任务队列
    ThreadFactory threadFactory,       // 线程工厂
    RejectedExecutionHandler handler   // 拒绝策略
);
```

**工作流程：**
1. 任务数 ≤ corePoolSize → 创建核心线程执行
2. 任务队列未满 → 放入队列等待
3. 队列满，且线程数 < maximumPoolSize → 创建临时线程
4. 队列满，线程数已达最大 → 执行拒绝策略

**拒绝策略：**
| 策略 | 行为 |
|------|------|
| AbortPolicy（默认） | 抛 RejectedExecutionException |
| CallerRunsPolicy | 调用者线程自己执行 |
| DiscardPolicy | 直接丢弃，不抛异常 |
| DiscardOldestPolicy | 丢弃队列中最旧的任务 |

### 1.5 手动创建线程池（推荐）

```java
ThreadPoolExecutor pool = new ThreadPoolExecutor(
    2,                      // 核心线程数
    5,                      // 最大线程数
    60,                     // 空闲存活时间
    TimeUnit.SECONDS,       // 时间单位
    new ArrayBlockingQueue<>(10), // 有界队列
    Executors.defaultThreadFactory(), // 默认线程工厂
    new ThreadPoolExecutor.AbortPolicy() // 拒绝策略
);
```

> 📌 **阿里巴巴开发手册：** 禁止使用 Executors 创建线程池，必须手动 new ThreadPoolExecutor，以避免资源耗尽（FixedThreadPool 的队列无界）。

## 二、并发工具类

### 2.1 CountDownLatch（倒计时门闩）

让一个线程等待其他 N 个线程完成后继续执行。

```java
// 创建：计数器 = 3
CountDownLatch latch = new CountDownLatch(3);

// 每个子线程完成时调用
latch.countDown();   // 计数器 -1

// 主线程等待
latch.await();       // 等待计数器归零
```

**示例：** 主线程等所有子线程加载完成再继续。

```java
public class CountDownLatchDemo {
    public static void main(String[] args) throws Exception {
        CountDownLatch latch = new CountDownLatch(3);

        for (int i = 0; i < 3; i++) {
            new Thread(() -> {
                System.out.println(Thread.currentThread().getName() + " 加载完成");
                latch.countDown();
            }).start();
        }

        latch.await(); // 等待所有线程完成
        System.out.println("主线程继续执行");
    }
}
```

### 2.2 CyclicBarrier（循环栅栏）

一组线程相互等待，都到达屏障后再同时继续。可循环使用。

```java
CyclicBarrier barrier = new CyclicBarrier(3, () -> {
    System.out.println("所有线程到达屏障，执行汇总任务");
});

// 每个线程
for (int i = 0; i < 3; i++) {
    new Thread(() -> {
        System.out.println(Thread.currentThread().getName() + " 到达屏障");
        barrier.await(); // 等待其他线程
        System.out.println(Thread.currentThread().getName() + " 继续执行");
    }).start();
}
```

**CountDownLatch vs CyclicBarrier：**

| | CountDownLatch | CyclicBarrier |
|--|---------------|---------------|
| 用途 | 一个线程等 N 个线程 | N 个线程互相等待 |
| 能否复用 | ❌ 一次性的 | ✅ 可重置 |
| 计数器方式 | 减 | 加 |

### 2.3 Semaphore（信号量）

控制同时访问资源的线程数量（限流）。

```java
Semaphore semaphore = new Semaphore(3); // 最多 3 个线程同时访问

// 获取许可
semaphore.acquire();  // 阻塞直到获得许可
// 或 tryAcquire()：尝试获取，不阻塞

// 释放许可
semaphore.release();
```

**示例：** 停车场限流。

```java
Semaphore spots = new Semaphore(3);

for (int i = 0; i < 10; i++) {
    new Thread(() -> {
        try {
            spots.acquire();
            System.out.println(Thread.currentThread().getName() + " 获得车位");
            Thread.sleep(2000); // 停车 2 秒
        } catch (InterruptedException e) {
            e.printStackTrace();
        } finally {
            System.out.println(Thread.currentThread().getName() + " 离开");
            spots.release();
        }
    }, "车" + i).start();
}
```

## 三、阻塞队列（BlockingQueue）

### 常用实现类

| 实现类 | 特点 |
|--------|------|
| ArrayBlockingQueue | 有界，数组结构，FIFO |
| LinkedBlockingQueue | 无界/有界，链表结构，FIFO |
| PriorityBlockingQueue | 支持优先级 |
| SynchronousQueue | 不存储元素，直接传递 |

### 常用方法

```java
BlockingQueue<String> queue = new ArrayBlockingQueue<>(5);

// 抛异常
queue.add("元素");          // 成功返回 true，满则抛异常
queue.remove();             // 移出头部，空则抛异常
queue.element();            // 查看头部，空则抛异常

// 特殊值
queue.offer("元素");        // 成功 true，满 false
queue.poll();               // 返回头部，空 null
queue.peek();               // 查看头部，空 null

// 阻塞
queue.put("元素");          // 满则阻塞等待
queue.take();               // 空则阻塞等待

// 超时
queue.offer("元素", 3, TimeUnit.SECONDS);  // 3 秒超时
queue.poll(3, TimeUnit.SECONDS);           // 3 秒超时
```

## 五、ForkJoin 框架

将大任务拆分成小任务并行执行（分治思想）。

```java
class SumTask extends RecursiveTask<Long> {
    private static final int THRESHOLD = 1000;
    private long[] arr;
    private int start, end;

    public SumTask(long[] arr, int start, int end) {
        this.arr = arr;
        this.start = start;
        this.end = end;
    }

    @Override
    protected Long compute() {
        if (end - start <= THRESHOLD) {
            long sum = 0;
            for (int i = start; i < end; i++) sum += arr[i];
            return sum;
        }
        // 拆分成两个子任务
        int mid = (start + end) / 2;
        SumTask left = new SumTask(arr, start, mid);
        SumTask right = new SumTask(arr, mid, end);
        left.fork();   // 异步执行
        right.fork();
        return left.join() + right.join(); // 合并结果
    }
}

// 使用
ForkJoinPool pool = new ForkJoinPool();
Long result = pool.invoke(new SumTask(arr, 0, arr.length));
```

## 六、多线程总结

### 线程安全的几种方式（从轻到重）

1. **volatile** → 保证可见性，不保证原子性
2. **AtomicXXX** → CAS 原子操作（轻量级无锁）
3. **synchronized** → 隐式锁，自动释放
4. **Lock** → 显式锁，功能更丰富
5. **并发工具类** → CountDownLatch / CyclicBarrier / Semaphore
6. **线程池** → 统一管理线程，避免频繁创建销毁
7. **并发集合** → ConcurrentHashMap / CopyOnWriteArrayList

### 开发实践建议

1. 优先使用线程池，不要 new Thread()
2. 线程池手动创建，别用 Executors
3. 高并发场景用 ConcurrentHashMap 而非 HashMap
4. 简单同步用 synchronized，复杂场景用 Lock
5. volatile 只适合标志位场景
6. 多线程调试用 jstack 分析线程 dump
