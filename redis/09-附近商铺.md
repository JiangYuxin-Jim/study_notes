# 08 - 附近商铺

## 业务场景

在类似黑马点评的项目中，用户可以选择按距离排序查看附近的商铺。本质就是 LBS（基于位置的服务）在 Redis 中的实现。

## Redis GEO 数据结构

Redis 3.2+ 提供了 GEO（地理空间）相关命令，底层基于 **SortedSet + GeoHash 编码** 实现。

### GeoHash 原理

- 将二维经纬度编码为一维字符串
- 字符串越长，位置越精确
- 字符串前缀相同的 GeoHash，地理位置越接近
- 因此可以用 SortedSet 的 score 来做范围查询

### 核心命令

| 命令 | 作用 | 示例 |
|------|------|------|
| `GEOADD` | 添加坐标 | `GEOADD key longitude latitude member` |
| `GEODIST` | 计算距离 | `GEODIST key member1 member2 [unit]` |
| `GEOSEARCH` | 范围搜索 | `GEOSEARCH key FROMLONLAT ... BYRADIUS ...` |
| `GEOSEARCHSTORE` | 搜索并存储结果 | |

## 实现商铺按距离排序

### 1. 缓存商铺 GEO 数据

在系统启动时或首次查询时，将商铺的经纬度写入 Redis：

```bash
GEOADD shop:geo 121.47 31.23 商铺ID1
GEOADD shop:geo 121.50 31.20 商铺ID2
```

### 2. 按距离查询

```bash
# 搜索指定经纬度附近 5km 内的商铺，返回坐标+距离
GEOSEARCH shop:geo FROMLONLAT 121.47 31.23 BYRADIUS 5 km WITHDIST WITHCOORD
```

### 3. 代码实现

```java
// 构建查询
GeoOperations<String, String> ops = stringRedisTemplate.opsForGeo();
RedisGeoCommands.GeoRadiusCommandArgs args = 
    GeoRadiusCommandArgs.newGeoRadiusArgs()
        .includeDistance()
        .includeCoordinates()
        .sortAscending()
        .limit(count);

// 执行查询
GeoResults<GeoLocation<String>> results = 
    ops.radius("shop:geo", 
        new Circle(new Point(lng, lat), new Distance(radius, Metrics.KILOMETERS)),
        args);

// 解析结果
List<Long> shopIds = new ArrayList<>();
Map<Long, Double> distanceMap = new HashMap<>();
for (GeoResult<GeoLocation<String>> result : results) {
    String shopId = result.getContent().getName();
    Double distance = result.getDistance().getValue();
    shopIds.add(Long.valueOf(shopId));
    distanceMap.put(Long.valueOf(shopId), distance);
}
```

### 4. 类型查询 & 分页

实际项目中，用户通常按商铺类型筛选（如"火锅""奶茶"），需要把不同类型的数据存到不同的 key 中：

```bash
# 按类型分 key
GEOADD shop:geo:type:{typeId} lng lat shopId
GEOADD shop:geo:type:1 121.47 31.23 101  # 美食类
GEOADD shop:geo:type:2 121.48 31.22 102  # 奶茶类
```

**GEO 的分页问题**：

`GEOSEARCH` 不支持 `OFFSET`，所以分页需要用业务代码实现：

```java
// 先多查一页
int queryCount = (currentPage) * pageSize;
GeoResults<?> results = ops.radius(... limit(queryCount));
// 手动截取当前页
int from = (currentPage - 1) * pageSize;
int to = Math.min(currentPage * pageSize, results.size());
List<GeoResult<?>> pageResults = results.subList(from, to);
```

## GEO 底层原理

> GEO 本质上就是 SortedSet，score 是 GeoHash 编码后的整数值。

- `GEOADD` = `ZADD` + 内部 GeoHash 编码
- `GEODIST` = 计算两个坐标之间的球面距离
- `GEORADIUS` = `ZRANGEBYSCORE` + 按距离过滤 + 按经纬度精确筛选

所以 GEO 本质上是对 SortedSet 的封装，加入了几何计算的能力。

## GEO 与 MySQL 空间索引对比

| 维度 | Redis GEO | MySQL Spatial |
|------|-----------|---------------|
| 性能 | 极高（内存） | 取决于磁盘 IO |
| 精度 | 可调（GeoHash 位数） | 精确几何计算 |
| 功能 | 基础距离查询 | 完整空间函数 |
| 场景 | 实时附近查询 | 复杂空间分析 |
