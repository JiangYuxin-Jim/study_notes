# 07 - 短信登录

> 📅 2026-07-29 | 🏷️ Redis / Session / 分布式登录 / 拦截器

---

## 1. 业务场景

用户通过**手机号 + 验证码**的方式登录，这是移动端最常见的登录方式。

```
1. 用户输入手机号 → 点击"获取验证码"
2. 服务端生成验证码 → 发送到手机（本项目模拟发送，直接控制台打印）
3. 用户输入验证码 → 点击"登录"
4. 服务端校验验证码 → 登录成功 → 保存用户登录状态
```

## 2. 基于 Session 的登录

### 2.1 Session 工作原理

```
1. 用户访问登录页面
2. 服务端创建 Session（会话对象）
3. 服务端将 SessionID 写入 Cookie（JSESSIONID）
4. 浏览器下次请求自动携带 Cookie
5. 服务端根据 SessionID 找到对应的 Session 对象
```

### 2.2 获取验证码

```java
@PostMapping("/code")
public Result sendCode(@RequestParam("phone") String phone, HttpSession session) {
    // 1. 校验手机号格式
    if (RegexUtils.isPhoneInvalid(phone)) {
        return Result.fail("手机号格式错误！");
    }

    // 2. 生成6位随机验证码
    String code = RandomUtil.randomNumbers(6);

    // 3. 保存验证码到 Session
    session.setAttribute("code:" + phone, code);

    // 4. 发送验证码（实际生产走短信通道，这里模拟打印）
    log.debug("验证码发送成功：{}", code);

    return Result.ok();
}
```

### 2.3 登录校验

```java
@PostMapping("/login")
public Result login(@RequestParam("phone") String phone,
                     @RequestParam("code") String code,
                     HttpSession session) {
    // 1. 校验手机号和验证码格式
    if (RegexUtils.isPhoneInvalid(phone)) {
        return Result.fail("手机号格式错误！");
    }
    if (RegexUtils.isCodeInvalid(code)) {
        return Result.fail("验证码格式错误！");
    }

    // 2. 从 Session 获取验证码并校验
    String cacheCode = (String) session.getAttribute("code:" + phone);
    if (cacheCode == null || !cacheCode.equals(code)) {
        return Result.fail("验证码错误或已过期！");
    }

    // 3. 查询用户（不存在则注册新用户）
    User user = query().eq("phone", phone).one();
    if (user == null) {
        user = createUserWithPhone(phone);
    }

    // 4. 保存用户信息到 Session（注意：不要存密码等敏感信息）
    session.setAttribute("user", BeanUtil.copyProperties(user, UserDTO.class));

    return Result.ok();
}
```

### 2.4 Session 方案的问题

```
单机 OK，但生产环境通常是集群部署：

┌───────┐      ┌──────────────┐
│ Nginx  │ ──→ │  服务 A (8081) │ ← Session 在 A 的内存中
│ 轮询   │ ──→ │  服务 B (8082) │ ← Session 在 B 的内存中
└───────┘      └──────────────┘

用户登录到了 A → Session 存在 A
下一个请求被 Nginx 转发到 B → B 没有这个 Session → 用户需要重新登录！
```

**这就是 Session 的分布式问题：Session 不能跨 JVM 共享。**

## 3. 基于 Redis 的短信登录

### 3.1 为什么用 Redis 替代 Session

| 对比项 | Session | Redis |
|--------|---------|-------|
| 存储位置 | 服务端内存 | 独立中间件 |
| 跨服务共享 | ❌ 不能 | ✅ 所有服务共用 |
| 持久化 | ❌ 重启丢失 | ✅ RDB/AOF |
| 过期机制 | 内置 | TTL 灵活控制 |
| 数据结构 | 仅键值对 | 丰富类型 |

### 3.2 验证码存 Redis

```java
@PostMapping("/code")
public Result sendCode(@RequestParam("phone") String phone) {
    // 1. 校验手机号
    if (RegexUtils.isPhoneInvalid(phone)) {
        return Result.fail("手机号格式错误！");
    }

    // 2. 生成验证码
    String code = RandomUtil.randomNumbers(6);

    // 3. 验证码存入 Redis，有效期 2 分钟（已学 + 防刷）
    stringRedisTemplate.opsForValue()
        .set("login:code:" + phone, code, 2, TimeUnit.MINUTES);

    log.debug("验证码：{}", code);
    return Result.ok();
}
```

**Key 设计：** `login:code:{phone}` — 业务前缀 + 手机号，便于管理

### 3.3 登录 — 用 Redis 校验 + Token 机制

```java
@PostMapping("/login")
public Result login(@RequestParam("phone") String phone,
                     @RequestParam("code") String code) {
    // 1. 校验参数
    if (RegexUtils.isPhoneInvalid(phone) || RegexUtils.isCodeInvalid(code)) {
        return Result.fail("参数格式错误！");
    }

    // 2. 从 Redis 获取验证码并校验
    String cacheCode = stringRedisTemplate.opsForValue().get("login:code:" + phone);
    if (StrUtil.isBlank(cacheCode) || !cacheCode.equals(code)) {
        return Result.fail("验证码错误！");
    }

    // 3. 查数据库（或注册新用户）
    User user = query().eq("phone", phone).one();
    if (user == null) {
        user = createUserWithPhone(phone);
    }

    // 4. 生成 Token（随机 UUID）
    String token = UUID.randomUUID().toString(true);

    // 5. 用户信息转 DTO 后存入 Redis（Hash 结构）
    UserDTO userDTO = BeanUtil.copyProperties(user, UserDTO.class);
    Map<String, Object> userMap = BeanUtil.beanToMap(userDTO,
        new CopyOptions()
            .setIgnoreNullValue(true)
            .setFieldValueEditor((name, value) -> value != null ? value.toString() : null)
    );

    String tokenKey = "login:token:" + token;
    stringRedisTemplate.opsForHash().putAll(tokenKey, userMap);

    // 6. 设置 Token 过期时间（30 分钟）
    stringRedisTemplate.expire(tokenKey, 30, TimeUnit.MINUTES);

    // 7. 返回 Token 给前端（前端存起来，每次请求携带）
    return Result.ok(token);
}
```

**为什么用 Token 不用 SessionID？**
- SessionID 是服务端生成的，存在 Cookie 里
- Token 是服务端生成的，存在 Redis 里，返回给前端
- 前端可以存在 LocalStorage 或请求头中，不依赖 Cookie
- 移动端（App/小程序）对 Cookie 支持不好，Token 更通用

### 3.4 登录校验 — 拦截器

```java
public class LoginInterceptor implements HandlerInterceptor {

    private StringRedisTemplate stringRedisTemplate;

    public LoginInterceptor(StringRedisTemplate stringRedisTemplate) {
        this.stringRedisTemplate = stringRedisTemplate;
    }

    @Override
    public boolean preHandle(HttpServletRequest request,
                              HttpServletResponse response,
                              Object handler) throws Exception {
        // 1. 从请求头获取 Token（前端约定放在 authorization 头中）
        String token = request.getHeader("authorization");
        if (StrUtil.isBlank(token)) {
            // 未登录，返回 401
            response.setStatus(401);
            return false;
        }

        // 2. 从 Redis 查询用户信息
        String key = "login:token:" + token;
        Map<Object, Object> userMap = stringRedisTemplate.opsForHash().entries(key);
        if (userMap.isEmpty()) {
            // Token 过期或无效
            response.setStatus(401);
            return false;
        }

        // 3. 将用户信息转为 DTO，存入 ThreadLocal
        UserDTO userDTO = BeanUtil.fillBeanWithMap(userMap,
            new UserDTO(), false);
        UserHolder.saveUser(userDTO);

        // 4. 刷新 Token 有效期（续期）
        stringRedisTemplate.expire(key, 30, TimeUnit.MINUTES);

        return true;
    }

    @Override
    public void afterCompletion(HttpServletRequest request,
                                 HttpServletResponse response,
                                 Object handler, Exception ex) {
        // 请求结束后清除 ThreadLocal，防止内存泄漏
        UserHolder.removeUser();
    }
}
```

### 3.5 注册拦截器

```java
@Configuration
public class WebMvcConfig implements WebMvcConfigurer {

    @Autowired
    private StringRedisTemplate stringRedisTemplate;

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(new LoginInterceptor(stringRedisTemplate))
                .addPathPatterns("/**")                        // 拦截所有
                .excludePathPatterns(                           // 放行登录相关
                    "/user/code", "/user/login",
                    "/blog/hot", "/shop/**",
                    "/shop-type/**", "/upload/**",
                    "/voucher/**"
                );
    }
}
```

## 4. ThreadLocal 详解

### 4.1 什么是 ThreadLocal

ThreadLocal 是 Java 提供的**线程局部变量**工具：

```java
public class UserHolder {
    private static final ThreadLocal<UserDTO> tl = new ThreadLocal<>();

    public static void saveUser(UserDTO user) {
        tl.set(user);  // 当前线程存一份
    }

    public static UserDTO getUser() {
        return tl.get();  // 当前线程取一份
    }

    public static void removeUser() {
        tl.remove();  // 防止内存泄漏
    }
}
```

### 4.2 ThreadLocal 原理

```
每个 Thread 对象内部有一个 ThreadLocalMap：
         Thread
    ┌──────────────┐
    │ ThreadLocalMap │
    │               │
    │ key: TL引用 → value: userDTO  │  ← 存在当前线程的 Map 里
    └──────────────┘

同一个线程的任何地方都能 get 到
不同线程之间互不干扰
```

**为什么用 ThreadLocal 然后 remove？**
- 拦截器里把用户信息存进去 → Controller 和 Service 里直接取
- 不用在每个方法参数里传 UserDTO
- 请求结束后必须 remove，否则线程池复用线程时，旧数据污染新请求

## 5. 登录拦截优化 — 双重拦截器

### 5.1 问题：有些接口不需要登录，但需要用户信息

```
首页热门笔记（/blog/hot）→ 不需要登录就能看
但如果有登录，点赞按钮要显示用户是否已点过赞

如果只用 LoginInterceptor：
- 加登录拦截 → 未登录用户看不了热门
- 不加拦截 → 已登录用户看不到自己的状态

怎么办？刷新 Token 和 身份校验 分开！
```

### 5.2 改进方案：刷新拦截器 + 登录拦截器

```java
/**
 * 第一层：刷新拦截器（所有请求都走）
 * 功能：只要有 Token，就刷新有效期 + 存入 ThreadLocal
 *      没有 Token 也放行（ThreadLocal 里就是 null）
 */
public class RefreshTokenInterceptor implements HandlerInterceptor {

    private StringRedisTemplate stringRedisTemplate;

    @Override
    public boolean preHandle(HttpServletRequest request,
                              HttpServletResponse response,
                              Object handler) {
        String token = request.getHeader("authorization");
        if (StrUtil.isNotBlank(token)) {
            String key = "login:token:" + token;
            Map<Object, Object> userMap =
                stringRedisTemplate.opsForHash().entries(key);
            if (!userMap.isEmpty()) {
                // 有用户信息 → 存 ThreadLocal + 续期
                UserDTO userDTO = BeanUtil.fillBeanWithMap(
                    userMap, new UserDTO(), false);
                UserHolder.saveUser(userDTO);
                stringRedisTemplate.expire(key, 30, TimeUnit.MINUTES);
            }
        }
        return true;  // 不管有没有 Token，都放行
    }
}

/**
 * 第二层：登录拦截器（需要登录的接口才走）
 * 功能：检查 ThreadLocal 里有没有用户信息
 *      没有 → 拦截（未登录）
 */
public class LoginInterceptor implements HandlerInterceptor {

    @Override
    public boolean preHandle(HttpServletRequest request,
                              HttpServletResponse response,
                              Object handler) throws Exception {
        // 检查 ThreadLocal（第一层已经放好了）
        if (UserHolder.getUser() == null) {
            response.setStatus(401);
            return false;
        }
        return true;
    }
}
```

### 5.3 注册两层拦截器

```java
@Configuration
public class WebMvcConfig implements WebMvcConfigurer {

    @Autowired
    private StringRedisTemplate stringRedisTemplate;

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        // 第一层：刷新拦截器（拦截所有）
        registry.addInterceptor(new RefreshTokenInterceptor(stringRedisTemplate))
                .addPathPatterns("/**")
                .order(0);  // 优先级最高

        // 第二层：登录校验（只拦截需要登录的）
        registry.addInterceptor(new LoginInterceptor())
                .addPathPatterns(
                    "/user/**", "/blog/like/**",
                    "/shop/**"
                )
                .excludePathPatterns(
                    "/user/code", "/user/login"
                )
                .order(1);
    }
}
```

**两层架构的优势：**

```
请求来了
    │
    ▼
┌─────────────────────────────┐
│ RefreshTokenInterceptor     │  ← 第1层（全部放行）
│ 有Token → 刷新 + 存用户      │
│ 无Token → 继续走（用户=null）│
└─────────────────────────────┘
    │
    ▼
┌─────────────────────────────┐
│  需要登录吗？                  │
│  ├─ 需要 → LoginInterceptor  │  ← 第2层
│  │    ├─ 用户存在 → 放行      │
│  │    └─ 用户null → 401      │
│  └─ 不需要 → 直接放行          │
└─────────────────────────────┘
    │
    ▼
   Controller / Service
   用户信息从 UserHolder.getUser() 获取
```

## 6. 关键知识点总结

| 内容 | 要点 |
|------|------|
| 验证码存储 | Redis + TTL 2分钟，`login:code:{phone}` |
| Token 机制 | UUID 生成，取代 SessionID，更通用 |
| 用户信息存储 | Redis Hash 结构，`login:token:{token}` |
| Token 续期 | 每次请求刷新 TTL = 30 分钟 |
| ThreadLocal | 当前线程存储用户信息，用完 remove |
| 双重拦截器 | 刷新拦截（全放行）+ 登录拦截（仅拦截需登录的） |
| 对比 Session | Redis 方案支持集群共享，Token 不依赖 Cookie |
