---

## 一、什么是 RESP 协议

- **RESP** = **RE**dis **S**erialization **P**rotocol（Redis 序列化协议）。
- 它是 Redis 客户端（如 Jedis、Lettuce、RedisTemplate）与 Redis 服务器之间**通信的语言**。
- 传输层基于 **TCP**，协议本身是**纯文本**的（人类可读、便于调试）。
- 版本演进：RESP2（经典）→ **RESP3**（Redis 6.0 引入，主要是新的数据类型支持，如 Map、Push 等）。

> 一句话：**RESP 协议就是"客户端用什么样的文本格式告诉 Redis 要执行什么命令、Redis 又用什么文本格式返回结果"的约定。**

---

## 二、RESP 的五种基础数据类型

RESP 协议中，每条消息的类型由**首字节**标识：

| 首字节 | 类型 | 含义 | 对应 Java 接收类型 |
|--------|------|------|------|
| `+` | **Simple String** 简单字符串 | 状态回复（成功类信息） | String |
| `-` | **Error** 错误 | 错误信息 | 抛异常 |
| `:` | **Integer** 整数 | 整数回复（如 INCR 结果、EXISTS 结果） | long |
| `$` | **Bulk String** 批量字符串 | 二进制安全的字符串（命令/值），长度前缀+内容 | String |
| `*` | **Array** 数组 | 多个元素组成的数组（命令参数、返回多条结果） | List/数组 |

> 协议格式统一为：**首字节(类型标志) + 长度(\r\n) + 内容(\r\n)**，行尾都用 `\r\n`（回车换行）分隔。

---

## 三、Resp 编码详解

### 1. 简单字符串 `+`
```
+OK\r\n
```
- 以 `+` 开头，后跟字符串内容，以 `\r\n` 结尾。
- 用于简单的状态回复，如 `SET` 成功返回 `+OK`。

### 2. 错误 `-`
```
-ERR unknown command 'foo'\r\n
```
- 以 `-` 开头，`ERR` 后是错误信息。
- 客户端收到后通常抛异常。

### 3. 整数 `:`
```
:1000\r\n
```
- 以 `:` 开头，后跟十进制整数，`\r\n` 结尾。
- 如 `EXISTS key` 返回 `:1`，`INCR` 返回 `:1000`。

### 4. 批量字符串 `$`
```
$5\r\nhello\r\n
```
- 以 `$` 开头，**第一行是内容的字节长度**（这里是 5，表示后面跟 5 个字节）。
- 第二行是实际内容，以 `\r\n` 结尾。
- **二进制安全**：长度预先声明，内容可以是任意字节，不会因为内容里含特殊字符而解析出错。
- 特殊情况：`$-1\r\n` 表示 **null**（nil），如 `GET` 不存在的 key 返回 `$-1`。

### 5. 数组 `*`
```
*2\r\n$3\r\nfoo\r\n$3\r\nbar\r\n
```
- 以 `*` 开头，`*2` 表示数组有 2 个元素。
- 每个元素再按各自类型编码（这里两个都是 Bulk String）。
- 用于**命令请求**（参数列表）和**多条结果**（如 `LRANGE`、`MGET` 的返回值）。

---

## 四、客户端与服务端的通信流程

### 一次命令请求（以 `SET name jack` 为例）
客户端把命令和参数组装成**数组 + 批量字符串**发送：

```
*3\r\n$3\r\nSET\r\n$4\r\nname\r\n$4\r\njack\r\n
```
- `*3`：命令 + 2 个参数 = 3 个元素。
- `$3 SET`：命令名。
- `$4 name`、`$4 jack`：两个参数。

服务端执行后返回：
```
+OK\r\n
```

### 一次查询请求（以 `GET name` 为例）
```
*2\r\n$3\r\nGET\r\n$4\r\nname\r\n
```
返回（若 key 存在）：
```
$4\r\njack\r\n
```
若 key 不存在则返回 `$-1\r\n`（null）。

> 结论：**客户端发命令 = `*` 数组（命令+参数）；服务端返回 = 看情况用简单字符串/整数/批量字符串/数组/错误。**

## 五、手写简易 RESP 客户端思路

理解了协议格式，就能用原生 Socket 手写一个"穷人的 Redis 客户端"：

1. 用 Socket 连接 Redis（默认端口 6379）。
2. 把命令拼接成 RESP 格式字符串（`*N\r\n$len\r\ncmd\r\n...`）。
3. 写入输出流发送给服务器。
4. 从输入流读取返回，按**首字节**判断类型并解析：
   - `+` → 读一行返回 String
   - `-` → 读一行抛异常
   - `:` → 读一行转 long
   - `$` → 读长度，再读对应字节内容
   - `*` → 读元素个数，循环解析每个元素（递归）

> 这一小节（结合课程代码）证明：**RESP 协议无关编程语言，只要能读写 TCP 流，就能实现任意语言的 Redis 客户端。**

---

## 六、核心要点速记

- **RESP** = Redis 序列化协议，基于 TCP，纯文本，客户端与服务端通信的"语言"。
- **五种类型**（首字节标识）：`+`简单字符串、`-`错误、`:`整数、`$`批量字符串（二进制安全）、`*`数组。
- **通用格式**：首字节 + 长度 + 内容 + `\r\n`。
- **命令请求** = `*` 数组（第 1 个元素命令名，后续为参数），参数多为批量字符串。
- **批量字符串**用 `$长度` 声明内容长度 → **二进制安全**；`$-1` 表示 null。
- **返回解析**：按首字节决定读法，数组需**递归**解析。
- **RESP3**（Redis 6.0）：新增 Map、Push 等类型，用于 RESP2 的扩展。
