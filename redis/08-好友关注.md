## 业务场景

在类似黑马点评的项目中，用户之间可以关注/取关，并能查看自己关注的人发布的探店笔记（Feed 流）。

## 关注与取关

### 数据库设计
- `tb_follow` 表：`id`, `user_id`, `follow_user_id`, `create_time`
- 关注：插入一条记录
- 取关：删除对应记录

### 判断是否已关注
```sql
SELECT COUNT(*) FROM tb_follow 
WHERE user_id = ? AND follow_user_id = ?
```

> 业务上通常不会对关注做太多 Redis 缓存，因为用户关系以关系型数据库为主。

## 共同关注

这是典型的社交场景——查看自己和某个好友共同关注了哪些人。

### 基于 Set 实现

```java
// 1. 获取当前用户的关注列表 -> Set<Long>
Set<Long> myFollows = ...;
// 2. 获取目标用户的关注列表 -> Set<Long>
Set<Long> targetFollows = ...;
// 3. 求交集
Set<Long> common = new HashSet<>(myFollows);
common.retainAll(targetFollows);
```

### Redis Set 优化

将关注列表同步到 Redis Set 中，利用 Set 的求交集操作：

```bash
SINTER user:1:follow user:2:follow
```

实际项目中，如果关注量不大（一般几百以内），直接用 Java 内存中的 HashSet 求交即可。如果关注量巨大（大 V），则用 Redis `SINTER`。

## Feed 流（关注推送）

核心需求：当用户关注的人发布了新笔记，用户能刷到。

### 常见实现模式

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| **推模式（Write Fanout）** | 发布时推送给所有粉丝，粉丝直接读 | 粉丝少的场景（如微信朋友圈） |
| **拉模式（Pull）** | 发布时不推，粉丝刷新时拉取关注人的内容 | 粉丝多的场景（如微博大 V） |
| **推拉结合** | 普通粉丝推，大 V 粉丝拉 | 混合场景 |

### 黑马点评的实现

使用**推模式**，因为用户量级不大，使用 **SortedSet** 存储 Feed：

```bash
# 发笔记时，推送给每个粉丝
ZADD user:{followerId}:feed {timestamp} {noteId}

# 粉丝滚动查 Feed
ZREVRANGEBYSCORE user:{followerId}:feed +inf 0 LIMIT 0 3
```

### 关键实现细节

1. **滚动分页**：用 `ZREVRANGEBYSCORE` 代替传统分页（`LIMIT offset, size`）
   - SortedSet 不支持 `OFFSET`，所以必须用**滚动查询**：
   - 每次查询记录最后一个元素的 score（时间戳），下次用 `ZREVRANGEBYSCORE +inf {lastScore} LIMIT 1 {size}`
   - 注意 `LIMIT` 参数：offset=1（跳过上一页最后一条），count=3

2. **为什么不用 `LIMIT 0, 4`？**
   - 因为 SortedSet 是**基于分数排序的**，不是基于索引
   - 滚动查询基于 score 值，不管中间跳过了多少条

3. **代码示例**：
```java
// 首次查询
Set<String> notes = stringRedisTemplate.opsForZSet()
    .reverseRangeByScore(key, 0, Long.MAX_VALUE, 0, 3);

// 滚动查询（取到 lastScore 后）
Set<String> notes = stringRedisTemplate.opsForZSet()
    .reverseRangeByScore(key, 0, lastScore - 1, 0, 3);
```

## 推模式的性能考虑

- 每次发笔记要遍历所有粉丝写入 SortedSet
- 如果有 10 万粉丝，一次发布 = 10 万次 ZADD
- 因此推模式只适合粉丝量不大的场景
- 大 V 场景需要推拉结合或纯拉模式

## 关键代码片段

```java
// 发笔记时推送给粉丝
Long userId = UserHolder.getUser().getId();
Set<String> followers = stringRedisTemplate.opsForSet()
    .members("followers:" + userId);
for (String followerId : followers) {
    String key = RedisConstants.FEED_KEY + followerId;
    stringRedisTemplate.opsForZSet()
        .add(key, noteId.toString(), System.currentTimeMillis());
}

// 滚动查询
int offset = lastId != null ? 1 : 0;
Set<ZSetOperations.TypedTuple<String>> tuples = 
    stringRedisTemplate.opsForZSet()
    .reverseRangeByScoreWithScores(key, 0, lastId, offset, pageSize);
```

## 总结

| 知识点 | 核心要点 |
|--------|---------|
| 关注/取关 | 数据库 CRUD + 判断是否关注 |
| 共同关注 | Set 交集（Java 或 Redis SINTER） |
| 推模式 Feed | 发布时写粉丝 SortedSet |
| 滚动分页 | ZREVRANGEBYSCORE + lastScore |
| 适用场景 | 推模式适合小 V，大 V 用拉/推拉结合 |
