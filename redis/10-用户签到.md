# 09 - 用户签到

> 📅 2026-07-30 | 🏷️ Redis / BitMap / 位图 / 连续签到

---

## 业务场景

用户每日签到功能——签到一天给积分，连续签到额外奖励。需要设计高效存储方案，支持：
1. 用户签到
2. 查询当月签到情况
3. 统计连续签到天数

## 为什么用 BitMap

### 传统方案
- 建一张 `tb_sign` 表，`user_id`, `sign_date`, `bonus`
- 一个月签到 30 天 = 30 条记录
- 上千万用户 = 亿级数据量

### BitMap 方案

一个用户的年签到数据只需要 365 bit ≈ 46 byte，省 99% 存储。

| 方案 | 存储量（1 年/用户） | 1000 万用户 |
|------|--------------------|------------|
| MySQL 行记录 | ~10KB | ~100GB |
| Redis BitMap | ~46B | ~460MB |

## BitMap 命令

```bash
# 签到：将第 day 位设为 1（day 表示当月的第几天）
SETBIT key offset 1

# 查询某天是否签到
GETBIT key offset

# 统计签到总天数
BITCOUNT key

# 批量操作
BITFIELD key GET u{bits} {start}
```

### 构建 Key

```
user:sign:{userId}:{yyyyMM}
```

例如：`user:sign:101:202607`

### offset 的确定

每月第一天 offset=0，第二天 offset=1，签到日就是 `dayOfMonth - 1`：

```java
// LocalDate.getDayOfMonth() 返回 1~31
int offset = now.getDayOfMonth() - 1;
stringRedisTemplate.opsForValue()
    .setBit(SIGN_KEY + userId + ":" + yyyyMM, offset, true);
```

## 统计连续签到

连续签到是指：从今天往前数，直到第一个未签到的日子。

### 思路

1. 获取当月全部签到位（BITFIELD 一次取 32 位）
2. 从今天对应的位开始，逐位往前遍历
3. 遇到 0 停止

```java
// 1. 一次取出当月的所有签到数据（取 31 位够用）
List<Long> result = stringRedisTemplate.opsForValue()
    .bitField(key, BitFieldSubCommands.create()
        .get(BitFieldSubCommands.BitFieldType
            .unsigned(now.getDayOfMonth()))
        .valueAt(0));

if (result == null || result.isEmpty()) return 0;
long bits = result.get(0) == null ? 0 : result.get(0);

// 2. 从今天开始往前数连续签到天数
int count = 0;
while (true) {
    // 右移 (dayOfMonth - count - 1) 位后 & 1 判断是否签到
    if ((bits >> (dayOfMonth - count - 1) & 1) == 1) {
        count++;
    } else {
        break;
    }
}
```

### 位运算图解

假设当月 5 天，签到情况 11101（第 1、2、3、5 天签到）：

```
bits = 0b11101 (29)
今天 = 第5天 = offset 4

第1步：bits >> 4 & 1 = 11101 >> 4 = 1 → 签到，count=1
第2步：bits >> 3 & 1 = 11101 >> 3 = 1 → 签到，count=2
第3步：bits >> 2 & 1 = 11101 >> 2 = 1 → 签到，count=3
第4步：bits >> 1 & 1 = 11101 >> 1 = 0 → 中断，count=3
```

### 跨月连续签到

- BITFIELD 只取当月数据，跨月连续签到需要额外逻辑
- 如果今天=1号，上个月最后几天续签到需要查上个月的 BITMAP
- 实际项目中先不考虑跨月连续签到的场景

## BITFIELD 详解

`BITFIELD` 可以把 BitMap 当作整型数组来操作：

```bash
# 从偏移 0 开始取 5 位无符号整数（查看当月前 5 天签到情况）
BITFIELD user:sign:101:202607 GET u5 0

# 递增某个位的值（+1）
BITFIELD user:sign:101:202607 INCRBY u1 4 1
```

参数解释：
- `u{bits}`：无符号整型，占 bits 位
- `i{bits}`：有符号整型
- `{offset}`：起始位偏移

### 为什么 BITFIELD 要一次取到当前日期？

```java
// 如果今天是 7 月 15 日
// 取 15 位无符号整数（15 bit 正好覆盖当月前 15 天）
int numBits = now.getDayOfMonth();
```

这样就把所有已过去的天数的签到数据一次取出，可以在 Java 中做位运算分析。

## 签到积分的业务设计

```
第1天签到：1 积分
第7天签到：7 积分
第30天签到：30 积分
累计签到：额外奖励
连续签到：加倍奖励
```

这些积分规则通常放在数据库或配置中心，不在代码中硬编码。

## 性能分析

| 操作 | 时间复杂度 | 说明 |
|------|-----------|------|
| SETBIT | O(1) | 单个位操作 |
| GETBIT | O(1) | 读取单日签到 |
| BITCOUNT | O(n) | n 为字节数，365bit ≈ 46B |
| BITFIELD | O(n) | 但 n 极小（30~365bit） |

## 总结

| 知识点 | 核心要点 |
|--------|---------|
| BitMap 本质 | 位数组，8 bit = 1 byte |
| 签到 Key | user:sign:{userId}:{yyyyMM} |
| offset | dayOfMonth - 1 |
| 连续签到 | BITFIELD 取数据后在 Java 中位运算 |
| BITFIELD | 将 BitMap 按整型段读取/写入 |
| 优势 | 极大节省存储空间 |
| 适用场景 | 签到、布尔标记、日活统计 |
