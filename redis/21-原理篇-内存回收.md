## 一、为什么要关注内存回收

- Redis 数据**全部在内存**中，内存是**有限且昂贵**的资源。
- 有 **TTL（过期时间）** 的 key 到点后并不会自动、立刻消失——需要 Redis 主动去清理（**过期删除**）。
- 当内存**使用超过上限**（`maxmemory`）时，Redis 还需要**决定淘汰哪些 key** 来腾出空间（**内存淘汰**）。
- 两者合称 **内存回收**：一个是"到期删除"，一个是"超限淘汰"。

---

## 二、过期键删除策略（处理有 TTL 的 key）

### 删除时机：惰性删除 vs 定期删除

**惰性删除（Lazy）**
- key 过期后**不立刻删**，等**下次访问**这个 key 时才检查：若已过期则删除并返回 nil。
- 优点：CPU 开销小（只在访问时判断，不主动扫描）。
- 缺点：**过期 key 若一直不被访问，会一直占着内存**（内存泄漏风险）。

**定期删除（Active）**
- Redis 通过 **serverCron**（周期性时间事件）**每隔一段时间**（默认每 100ms 执行一次）**抽样扫描**部分过期 key 并删除。
- 优点：能主动清理一部分过期 key，缓解惰性删除的内存占用问题。
- 缺点：是**抽查**不是全扫，可能扫不到全部过期 key。

### 两种策略配合使用
- Redis 实际是**惰性删除 + 定期删除结合**：
  - 访问时惰性删除保证"读到的一定是没过期的"。
  - 定期删除保证"过期 key 不会无限堆积"。
- 但即便如此，仍可能出现"过期了但没被删、也没被访问"的 key 一直占内存 → 需要**内存淘汰**兜底。

> 一句话：**惰性删除 = 用到才删；定期删除 = 定时抽查删。两者配合。**

## 三、内存淘汰策略（处理内存超限）

当 Redis 内存达到 `maxmemory` 上限，写入新 key 时就会触发**内存淘汰**。策略通过 `maxmemory-policy` 配置，主要分几类：

### 按作用域分：全体 vs 过期key
| 作用域 | 说明 |
|--------|------|
| `allkeys-*` | 从**所有 key** 中淘汰（包括没过期的） |
| `volatile-*` | 只从**设了过期时间的 key** 中淘汰 |

### 按算法分
| 策略 | 说明 |
|------|------|
| `allkeys-lru` / `volatile-lru` | **LRU**：淘汰**最近最少使用**的 key（最久没被访问的） |
| `allkeys-lfu` / `volatile-lfu` | **LFU**：淘汰**使用频率最低**的 key（Redis 4.0 引入） |
| `allkeys-random` / `volatile-random` | **随机**淘汰 |
| `volatile-ttl` | 淘汰**剩余 TTL 最短**（最快过期）的 key |
| `noeviction` | **默认**：不淘汰，内存满了**拒绝写入**返回错误 |

### LRU vs LFU（重点对比）
- **LRU（Least Recently Used）最近最少使用**：看"**多久没被访问**"，淘汰最久没动过的。适合"热点数据集中、冷热分明"。
- **LFU（Least Frequently Used）最低频使用**：看"**访问次数多少**"，淘汰访问频率最低的。适合对付**偶发热点**：避免一个 key 偶尔被大量访问一次就长期占用（LRU 的缺陷）。
- Redis 的 LRU/LFU 都是**近似算法**（非严格全量统计），用**抽样 + 位域计数**近似实现，兼顾性能和内存。

> Redis 默认 `maxmemory-policy = noeviction`：内存满了**报错不写**，适合缓存之外的场景（如作为数据库使用）；做**缓存**时一般改成 `allkeys-lru` 或 `allkeys-lfu`。

## 四、手写 LRU 算法实现思路

面试/理解层面常考：如何（在 Java 等语言里）实现一个 LRU 缓存？**推荐 双向链表 + HashMap**：

1. **HashMap**：实现 O(1) 的 key → 节点定位。
2. **双向链表**：维护访问顺序，表头是"最近使用"，表尾是"最久未使用"。
3. 访问 key 时：查到节点 → **移到链表头部**。
4. 插入新 key 时：放到链表头部；若容量满了，**删除链表尾部节点**（最久未使用）。

- 也可以直接用 Java 的 `LinkedHashMap`（`accessOrder=true` + 重写 `removeEldestEntry`）快速实现。
- 复杂度：**get / put 都是 O(1)**。

> 要点：**LRU 核心 = "访问即置顶，满了删尾部"。**

## 五、核心要点速记

- **过期删除两种**：惰性删除（用到才删，CPU 省内存可能漏）、定期删除（serverCron 定时抽查主动删）。**两者结合**。
- **内存淘汰触发**：内存达 `maxmemory` 上限写新 key 时。
- **作用域**：`allkeys-*`（全体淘汰）vs `volatile-*`（只淘汰过期 key）。
- **算法**：`lru`（最近最少用）、`lfu`（最低频用）、`random`（随机）、`ttl`（最快过期）、`noeviction`（默认，满了拒绝写）。
- **LRU vs LFU**：LRU 看"多久没用"，LFU 看"用得多不多"；LFU 更能应对偶发热点。
- **手写 LRU**：双向链表 + HashMap，get/put 均 O(1)，"访问置顶、满删尾部"。
