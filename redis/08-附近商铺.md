## 1. GEO 数据结构

### 1.1 什么是 GEO？

GEO（Geolocation，地理位置）是 Redis 3.2+ 提供的**地理空间索引**类型，底层基于 **Sorted Set + GeoHash 编码**实现。

```
本质：
GEO 底层就是 Sorted Set（ZSET）
  - value 仍然是 member（商铺ID）
  - score 是 GeoHash 编码后的经纬度整数
```

### 1.2 为什么用 GEO 不用 ZSET？

| 操作 | 原生 ZSET | GEO |
|------|-----------|-----|
| 存储经纬度 | 需要自己编码 | 直接存 `(lng, lat)` |
| 计算距离 | 需要自己算 | `GEODIST` 直接出结果 |
| 范围搜索 | 需要自己实现 | `GEOSEARCH` 按圆形/矩形搜索 |
| 按距离排序 | 需要自己实现 | 自动按距离排序 |

### 1.3 GEO 核心命令

```redis
# 添加地理位置
GEOADD key lng lat member [lng lat member ...]

# 计算两个成员之间的距离，单位 m/km/mi/ft
GEODIST key member1 member2 [m|km|mi|ft]

# 搜索范围内的成员
GEOSEARCH key [FROMMEMBER member | FROMLONLAT lng lat]
            [BYRADIUS radius m|km|mi|ft | BYBOX width height m|km|mi|ft]
            [ASC|DESC] [COUNT count [ANY]]
```

**示例：**

```redis
# 添加商铺坐标
GEOADD shops 116.397128 39.916527 "天安门"
GEOADD shops 116.326760 39.914734 "故宫"
GEOADD shops 116.345631 39.928546 "景山公园"

# 天安门到故宫的距离
GEODIST shops 天安门 故宫 km
# → "1.2345"（公里）

# 从天安门出发，搜索半径5公里内的商铺
GEOSEARCH shops FROMMEMBER 天安门 BYRADIUS 5 km ASC
# → 1) 天安门 2) 景山公园 3) 故宫

# 从指定坐标搜索
GEOSEARCH shops FROMLONLAT 116.4 39.91 BYRADIUS 3 km ASC COUNT 5
```

## 2. GEO 底层原理

### 2.1 GeoHash 编码

GeoHash 是一种将**二维经纬度编码为一维字符串**的算法：

```
1. 将地球划分为网格
2. 二分递归：若坐标在左/上 → 0，在右/下 → 1
3. 反复二分直到满足精度 → 得到二进制串
4. Base32 编码 → 得到字符串
```

```
                经度(-180, 180)
               ┌─────────────┐
               │  (0,0)      │  ← 第1次二分
               │             │
 纬度(-90,90) │     ●       │
               │             │
               └─────────────┘

北京天安门的 GeoHash: wx4g0f（6位 ≈ ±610m精度）
```

**GeoHash 的特性：**
- **前缀匹配**：GeoHash 前缀相同的坐标，地理位置相近
- **精度可调**：编码越长，格子越小，精度越高
- **边界问题**：两个很近的点可能在格子边界，编码完全不同（需要用 9 宫格搜索）

### 2.2 为什么 GEO 底层用 SortedSet

GeoHash 编码后得到一个整数值，这个值天然可以作为 SortedSet 的 score：

```
GeoHash(116.397, 39.916) = 4069885531023323（score）
Member: "商铺ID"

→ 放入 ZSET 后，按 score 排序 = 按地理位置排序
→ ZRANGEBYSCORE 可以查区间内的点
```

## 3. 附近商铺功能实现

### 3.1 业务场景

用户打开 App，点击"附近商铺"，按距离排序展示附近的店铺列表。

```
用户位置（经纬度）
     ↓
搜索 Redis GEO → 半径 5km 内的商铺
     ↓
按距离从近到远排序 → 分页返回
```

### 3.2 数据结构设计

```
Key:   shop:geo:{typeId}    （按商铺类型分 key，减少数据量）
Type:  GEO (ZSET)
Value: 商铺ID → score为GeoHash
```

**为什么要按 typeId 分 key？**
- 一个城市可能有数十万商铺
- 按美食/酒店/景点分类搜索，数据量更小，速度更快
- 单个 ZSET 控制在百万级以内，性能最优

### 3.3 店铺坐标数据导入

```java
// 商家入驻/更新时，将坐标写入 Redis GEO
@PostConstruct
public void loadShopGeo() {
    // 查询所有商铺
    List<Shop> shopList = shopService.list();

    for (Shop shop : shopList) {
        String key = "shop:geo:" + shop.getTypeId();

        // GEOADD shop:geo:typeId lng lat shopId
        stringRedisTemplate.opsForGeo()
            .add(key, new Point(shop.getX(), shop.getY()), shop.getId().toString());
    }
}
```

### 3.4 查询附近商铺

```java
@GetMapping("/shop/of/type")
public Result queryShopByType(
        @RequestParam("typeId") Long typeId,
        @RequestParam("current") Integer current,
        @RequestParam("x") Double x,      // 用户经度
        @RequestParam("y") Double y       // 用户纬度
) {
    String key = "shop:geo:" + typeId;

    // GEOSEARCH key FROMLONLAT x y BYRADIUS 5 km ASC
    GeoResults<RedisGeoCommands.GeoLocation<String>> results = stringRedisTemplate
        .opsForGeo()
        .search(
            key,
            GeoReference.fromCoordinate(x, y),         // 参考点
            new Distance(5000, RedisGeoCommands.DistanceUnit.METERS),  // 半径5km
            RedisGeoCommands.GeoSearchCommandArgs.newGeoSearchArgs()
                .includeDistance()    // 返回距离
                .sortAscending()      // 按距离升序
                .limit(current * 10)  // 分页
        );

    // 解析结果
    if (results == null) return Result.ok(Collections.emptyList());

    List<Long> ids = new ArrayList<>(results.size());
    HashMap<Long, Double> distanceMap = new HashMap<>();

    results.forEach(result -> {
        Long shopId = Long.valueOf(result.getContent().getName());
        ids.add(shopId);
        distanceMap.put(shopId, result.getDistance().getValue());
    });

    // 查 MySQL 商铺详情
    String idStr = StrUtil.join(",", ids);
    List<Shop> shops = shopService.query()
        .in("id", ids)
        .last("ORDER BY FIELD(id," + idStr + ")")
        .list();

    // 将距离信息注入返回对象
    shops.forEach(shop -> shop.setDistance(distanceMap.get(shop.getId())));

    return Result.ok(shops);
}
```

## 4. GEO 的限制与注意事项

### 4.1 GeoHash 的边界问题

```
想象两个点在地图上的格子边界：
┌───────┬───────┐
│  A    │   B   │  ← A和B实际距离很近（不到100米）
│       │       │    但GeoHash编码不同
└───────┴───────┘

搜索A附近的点时，B可能因为Grid划分被排除！
```

**解决方案：9宫格搜索**
- Redis 的 GEOSEARCH 底层已经自动做了 9 宫格扩展（查询时扩大范围），不需要自己处理

### 4.2 性能

| 数据量 | ZSET 大小 | GEOSEARCH 耗时 |
|--------|-----------|---------------|
| 10万 | 约 1.6MB（存 ID） | 微秒级 |
| 100万 | 约 16MB | 毫秒级 |
| 1000万 | 约 160MB | 数毫秒级 |

- 单个 GEO ZSET 建议不超过 1000 万元素
- 按 typeId 分 key 是常用的优化策略
