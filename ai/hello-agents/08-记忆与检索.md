## 8.1 从认知科学到智能体记忆

### 8.1.1 人类记忆系统的启发

参考认知科学，人类记忆形成经历 5 个阶段，可映射为技术组件：

1. **编码（Encoding）**：把感知信息转成可存储形式 → 数据预处理/向量化
2. **存储（Storage）**：把编码后信息存入记忆系统 → 各类存储/向量库
3. **检索（Retrieval）**：按需从记忆提取相关信息 → 搜索/召回
4. **整合（Consolidation）**：短期记忆转长期记忆 → 记忆层级晋升/压缩
5. **遗忘（Forgetting）**：删除不重要或过时信息 → 遗忘机制/淘汰策略

> 💡 核心设计思想：**模仿人类大脑处理不同类型信息的方式**，把记忆分成多个专门模块，并建立一套智能管理机制（添加 → 检索 → 整合 → 遗忘）。

### 8.1.2 为何智能体需要记忆与 RAG

- **LLM 天生"健忘"**：一次对话中上下文有限，会话结束即丢，无法记住用户偏好、历史经验。
- **LLM 知识有截止日期 + 会幻觉**：训练数据有时间截点，私有/实时知识不知道；编造答案造成幻觉。
- **记忆**解决"记住过去"（个性化、经验、上下文连续）；**RAG** 解决"获取新知识"（外部库、实时、可溯源），二者互补。

### 8.1.3 记忆与 RAG 系统架构设计（HelloAgents 落地）

延续第七章"**万物皆为工具**"的设计理念——Memory 和 RAG 在本框架中都被抽象为**工具（Tool）**，通过统一注册机制挂到 Agent 上，调用方式与普通工具一致。

- 记忆工具 `MemoryTool`
- RAG 工具 `RAGTool`
- 二者都实现同一套 `Tool` 基类接口，Agent 通过工具注册表统一管理。

## 8.2 记忆系统：让智能体拥有记忆

### 8.2.1 四种记忆模块（核心 ⭐）

| 记忆类型 | 角色 | 内容 | 生命周期 |
|---------|------|------|---------|
| **工作记忆 Working** | 短期记忆 | 当前对话上下文 | 容量受限（默认 50 条），随会话结束清理 |
| **情景记忆 Episodic** | 长期·具体事件 | 过往交互事件、学习经历（含上下文） | 长期，支持按时间/主题回顾，是"复盘"基础 |
| **语义记忆 Semantic** | 长期·抽象知识 | 用户偏好、长期指令、领域概念规则 | 高度持久、重要，是"知识体系"与关联推理核心 |
| **感知记忆 Perceptual** | 多模态 | 图像、音频等多媒体信息 | 按重要性/存储空间动态管理，支持跨模态检索 |

### 8.2.2 分层设计：MemoryTool ↔ MemoryManager（关注点分离）

- **MemoryTool**：面向用户的统一入口，处理参数、角色（是 Agent 看到的"记忆工具"）。初始化时按 `memory_types` 配置创建 MemoryManager 并启用对应记忆类型。
- **MemoryManager**：核心协调者，负责具体记忆逻辑。统一管理：
  - `MemoryStore`：底层存储
  - `MemoryRetriever`：检索
  - 各类型记忆模块（WorkingMemory / EpisodicMemory / SemanticMemory / PerceptualMemory），可按需开关（`enable_working` 等），避免资源浪费。

```python
class MemoryManager:
    def __init__(self, config=None, user_id="default_user",
                 enable_working=True, enable_episodic=True,
                 enable_semantic=True, enable_perceptual=False):
        self.store = MemoryStore(self.config)
        self.retriever = MemoryRetriever(self.store, self.config)
        self.memory_types = {}
        if enable_working:     self.memory_types['working'] = WorkingMemory(...)
        if enable_episodic:    self.memory_types['episodic'] = EpisodicMemory(...)
        if enable_semantic:    self.memory_types['semantic'] = SemanticMemory(...)
        if enable_perceptual:  self.memory_types['perceptual'] = PerceptualMemory(...)
```

### 8.2.3 MemoryTool 详解：关键操作

- **添加记忆**：`add(content, memory_type=...)` 指定类型存储
- **搜索检索**：`search(query, memory_type=..., top_k=...)`
  - 基础搜索 / 指定记忆类型搜索 / 多类型搜索（如同时查 working + semantic）
- **整合（Consolidation）**：把重要工作记忆晋升为情景记忆，再把重要情景记忆晋升为语义记忆——模拟"短期 → 长期"固化。
- **遗忘机制（Forgetting）**，三种策略：
  1. **基于重要性**：删除重要性低于阈值的记忆
  2. **基于时间**：删除超过指定天数的记忆
  3. **基于容量**：记忆超限时删最不重要的

> 💡 关键点：记忆不是"无限堆积"，通过**整合 + 遗忘**形成健康的知识沉淀与更新机制，类似人脑的遗忘曲线与记忆巩固。

## 8.3 RAG 系统：知识检索增强

### 8.3.1 什么是 RAG

**检索增强生成（Retrieval-Augmented Generation）** = 检索 + 增强 + 生成：在生成回答前先从外部知识库检索相关信息，作为上下文提供给 LLM，从而生成更准确、可溯源的答案。

**基本流程**：
- 数据准备阶段：**数据提取 → 文本分割 → 向量化**，构建可检索知识库
- 应用阶段：**提问 → 检索 → 注入 Prompt → LLM 生成答案**

**发展三阶段**：
1. **朴素 RAG（Naive, 2020-21）**：Retrieve-Read 模式，关键词匹配（TF-IDF/BM25），文档直接拼进 prompt，难懂语义
2. **高级 RAG（Advanced, 2022-23）**：转稠密嵌入（Dense Embedding）语义检索，引入查询重写、文档分块、重排序等优化
3. **模块化 RAG（Modular, 2023-至今）**：可插拔/可组合模块，混合检索、多查询扩展、假设性文档嵌入、思维链推理、自我反思修正

### 8.3.2 RAG 系统工作原理（5 层 7 步架构 ⭐）

两种工作模式：
1. **数据处理流程**：用工具 `Markitdown` 把一切外部知识源**统一转成 Markdown** 再处理（PDF/Office/图片/音频等多格式）
2. **查询与生成流程**：按查询检索并生成回答

**"五层七步"分层设计**（每层可独立优化/替换，如嵌入模型可从 sentence-transformers 切到百炼 API 不影响上层）：

```
用户层：RAGTool 统一接口
  ↓
应用层：智能问答、搜索、知识库管理
  ↓
处理层：文档解析、分块、向量化
  ↓
存储层：向量数据库（Qdrant 等）、文档存储
  ↓
基础层：嵌入模型、LLM、数据库
```

`RAGTool(Tool)` 作为统一入口，提供：添加多格式文档、智能检索召回、LLM 增强问答、知识库管理。

### 8.3.3 高级检索策略
- 混合检索（稀疏 BM25 + 稠密向量）、重排序（Rerank）提升召回质量
- 多查询扩展、假设性文档嵌入（HyDE）等进阶手段

## 8.4 构建智能文档问答助手（综合实战）

把记忆 + RAG 组合成一个完整应用：对文档进行问答。

- **案例背景**：用户在知识库中放入文档，助手能基于这些文档回答，并提供来源。
- **核心助手类**：集成 `MemoryTool`（记录对话上下文/用户偏好）+ `RAGTool`（检索文档知识）。
- **智能问答功能**：查询 → RAG 检索相关片段 → LLM 结合记忆与检索结果生成带来源的答案。
- **其他功能**：知识库管理（增删文档）、对话记忆保持、多轮上下文。

> 💡 架构价值：记忆负责"记住你是谁、聊过什么"，RAG 负责"知道文档里有什么"，两者作为工具被 Agent 统一调度——正好呼应第七章"万物皆为工具"。

## 8.5 本章总结

1. **记忆系统**：四种记忆（工作/情景/语义/感知）+ MemoryManager 统一管理，支持添加、检索、整合、遗忘，仿照认知科学设计。
2. **RAG 系统**："五层七步"架构 + Markitdown 统一转换 + 向量库检索增强，让 LLM 接入外部/实时知识并减少幻觉。
3. **综合落地**：记忆 + RAG 组合成智能文档问答助手，Agent 通过统一工具机制调用二者。
4. **设计理念延续**：记忆和 RAG 都作为"工具"存在，与第七章框架无缝衔接，符合"万物皆为工具"的统一抽象。
