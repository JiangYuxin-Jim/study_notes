## 一、语言模型与 Transformer 架构

### 1.1 从 N-gram 到 RNN（语言模型演进）

**语言模型 (LM)** 的根本任务：计算一个词序列（句子）出现的概率 `P(S)`。

**（1）统计语言模型与 N-gram**

- 核心思想：句子概率 = 各词条件概率连乘（**概率链式法则**）
  `P(S)=P(w1)·P(w2|w1)·P(w3|w1,w2)···P(wm|w1..w_{m-1})`
- 直接计算不可行 → 引入**马尔可夫假设**：一个词的出现只与前面有限 n-1 个词有关
- **N-gram 模型**：N=上下文窗口大小
  - Bigram (N=2)：`P(wi|w1..w_{i-1}) ≈ P(wi|w_{i-1})`
  - Trigram (N=3)：只看前两个词
- 概率用**最大似然估计 (MLE)**：看到最多的就是最可能的
  `P(wi|w_{i-1}) = Count(w_{i-1},w_i)/Count(w_{i-1})`

> 💡 手动算例：语料 `datawhale agent learns, datawhale agent works`（共6词），Bigram 求 `P(datawhale agent learns)`：
> ① `P(datawhale)=2/6≈0.333` ② `P(agent|datawhale)=2/2=1` ③ `P(learns|agent)=1/2=0.5` → 连乘 ≈ 0.167

**N-gram 的两大致命缺陷：**
1. **数据稀疏性**：没见过的词序列概率为 0（平滑只能缓解无法根除）
2. **泛化能力差**：无法理解词间语义相似（`robot learns` 若 `robot` 没出现过 → 概率为0，不知 agent≈robot）

**（2）神经网络语言模型与词嵌入**

- 2003 年 Bengio 提出前馈神经网络语言模型，里程碑意义
- 核心思想两步：
  1. 构建**语义空间**：把每个词映射成高维连续向量 → **词嵌入 (Word Embedding)**，语义近的词向量距离近
  2. 学习"上下文→下一个词"的映射函数
- **余弦相似度**衡量向量关系：`cos(θ)=(a·b)/(|a||b|)`，同向=1、正交=0、反向=-1
- 经典例子：`vector(King) - vector(Man) + vector(Woman) ≈ vector(Queen)`，证明词向量能捕捉"性别/皇室"等抽象概念
- 解决泛化问题，但仍是**固定上下文窗口** → 为 RNN 埋下伏笔

**（3）RNN 与 LSTM**

- **RNN**：引入**隐藏状态**作为"短期记忆"，每步读入当前词 + 上一步记忆，产出新记忆传给下一步，信息可沿序列传递
- 问题：**长期依赖问题**——序列长=网络深，反向传播梯度连乘 → **梯度消失/梯度爆炸**，难以捕捉长距离依赖
- **LSTM**（特殊 RNN）：引入**细胞状态**（信息通路的"传送带"）+ **门控机制**：
  - **遗忘门**：决定丢弃细胞状态里哪些旧信息
  - **输入门**：决定存入哪些新信息
  - **输出门**：决定输出哪些到隐藏状态

### 1.2 Transformer 架构解析

RNN 必须**按顺序**处理（第 t 步等第 t-1 步），无法并行、长序列效率低。2017 年谷歌提出 Transformer：**完全抛弃循环，完全依赖注意力 (Attention) 机制**，实现真正并行。

**（1）Encoder-Decoder 整体结构**（最初为机器翻译设计）

- **编码器 (Encoder)**：负责"理解"整个输入句子，为每个词元生成含上下文信息的向量
- **解码器 (Decoder)**：负责"生成"，参考已生成前文 + "咨询"编码器结果，生成下一个词
- 每个 Encoder/Decoder 层 = 多头自注意力 + 前馈网络 + 残差连接&层归一化（Add & Norm）

**（2）从自注意力到多头注意力**

自注意力即对"读到 it 会关注 agent"这类现象的数学建模。

- Q/K/V 三个可学习角色：
  - **查询 Query (Q)**：当前词元，主动"查询"其他词
  - **键 Key (K)**：可被查询的"标签/索引"
  - **值 Value (V)**：词元本身带的"内容/信息"
- 计算步骤（像一场开卷考试）：
  1. 每个词用权重矩阵 W^Q/W^K/W^V 生成 Q,K,V
  2. 用 Q 点乘所有词的 K → 相关性得分
  3. 除以缩放因子 √d_k 防梯度消失，再 Softmax 归一化成权重
  4. 权重 × 各 V 加权求和 → 融合全局上下文的词新表示
- 公式：`Attention(Q,K,V) = softmax(QK^T/√d_k)·V`

**多头注意力 (Multi-Head)**：把 Q,K,V 维度切成 h 份（h 个头），各自独立做单头注意力（相当于 h 个"专家"从不同视角看句子，捕捉指代/时态/从属等不同关系），最后拼接 + 线性变换整合。

**（3）前馈网络 (FFN)**

- 每个注意力子层后跟"逐位置前馈网络"，从聚合信息中提取高阶特征
- "逐位置"= 独立作用于每个词元向量，所有位置共享同一组权重（省参数）
- 结构：`FFN(x)=max(0, xW1+b1)·W2+b2`，先扩大（d_ff≈4·d_model）再缩小回 d_model

**（4）残差连接与层归一化 (Add & Norm)**

- **残差连接 (Add)**：`Output = x + Sublayer(x)`，解决深度网络的**梯度消失**，梯度可绕开子模块直传
- **层归一化 (Norm)**：对单个样本所有特征归一化（均值0方差1），解决**内部协变量偏移**，加速收敛、训练稳定

**（5）位置编码**

- 自注意力本身不含顺序/位置信息（"agent learns"和"learns agent"对它等价）→ 需加位置信息
- **位置编码 (Positional Encoding)**：给每个词元嵌入加上一个**固定公式算出的位置向量**（非学习）
- 原论文用正弦/余弦：
  `PE(pos,2i)=sin(pos/10000^(2i/d))`，`PE(pos,2i+1)=cos(pos/10000^(2i/d))`
- 同词不同位置 → 向量独一无二

### 1.3 Decoder-Only 架构

OpenAI 开发 GPT 时的简化思想：**语言的核心任务不就是预测下一个词吗？** 回答问题/写故事/写代码本质都是逐词续写最合理的内容。

- **GPT 完全抛弃编码器，只保留解码器** → Decoder-Only
- 工作模式**自回归 (Autoregressive)**：给起始文本 → 预测下一个词 → 把新词拼到末尾 → 再预测下一个 → 循环直到停止（如"文字接龙"）
- 如何防止"偷看"后面答案？→ **掩码自注意力 (Masked Self-Attention)**：注意力分数矩阵在 Softmax 前，把所有当前位置之后的词元分数替换为极大负数，Softmax 后概率变 0，从数学上阻止模型关注未来信息

**Decoder-Only 优势：**
1. **训练目标统一**：唯一任务"预测下一个词"，适合海量无标注文本预训练
2. **结构简单易扩展**：组件少，利于扩展成 GPT-4/Llama 等千亿万亿参数巨模型
3. **天然适合生成任务**：自回归模式与对话/写作/代码生成完美契合——这是它能成为通用智能体基础的核心原因

## 二、与大语言模型交互

### 2.1 提示工程（Prompt Engineering）

**（1）模型采样参数**（调整输出的随机性/多样性）

- **Temperature（温度）**：控制"随机性 vs 确定性"。改写 Softmax 为 `p_i = e^(z_i/T)/Σe^(z_j/T)`
  - T 小 → 分布更陡峭，输出更"保守、确定"（适合事实性任务：问答/代码/法律/学术）
  - T 大 → 分布更平坦，输出更"多样发散"（适合创意任务：诗歌/脑暴/故事）
  - 中 T → 平衡自然（日常对话/常规创作）
- **Top-k**：只保留概率最高前 k 个 token 组成候选集，再归一化采样。k=1 退化为贪心（完全确定）
- **Top-p**：从最高概率开始累加直到累积概率 ≥ p，动态选"核集合"，对分布长尾适应更好
- **协同优先级**：温度调整 → Top-k → Top-p（分层过滤）。但通常 Top-k 和 Top-p 二选一即可；若温度为0则 Top-k/Top-p 无关紧要，若 Top-k=1 则温度/Top-p 无关紧要

**（2）零样本/单样本/少样本提示**（按示例数量分）

- **零样本 (Zero-shot)**：不给示例直接下指令，靠预训练泛化能力（如直接"文本:...情感:正面"）
- **单样本 (One-shot)**：给 1 个完整"问题-答案"示例示范格式
- **少样本 (Few-shot)**：给多个覆盖不同情况的示例，让模型更准掌握任务边界和细节

**（3）指令调优的影响**

- 早期 GPT-3 是"**文本补全**"模型，擅长续写不一定懂执行指令 → 需用少样本"教会"它
- **指令调优 (Instruction Tuning)**：用大量"指令-回答"数据微调 → 模型能直接理解并遵循指令（现在用的 ChatGPT/DeepSeek/Qwen 都是调优过的模型），交互极大简化

**（4）基础提示技巧**

- **角色扮演**：赋予角色引导回答风格/语气/知识范围（如"你是资深Python专家，用初学者能懂的方式解释GIL"）
- **上下文示例**：类似少样本，提供输入输出示例"教会"模型处理复杂/特定格式任务（如要求严格 JSON 输出）

**（5）思维链 (Chain-of-Thought, CoT)**

- 复杂推理（多步计算/逻辑）直接给答案易出错
- 加引导语"请一步步思考 / Let's think step by step" → 显式展示推理过程
- 好处：更容易答对 + 回答更可信可检查可纠错

### 2.2 文本分词（Tokenization）

计算机只懂数字，文本需先转成数字序列 → **分词**，最小单元叫 **词元 (Token)**。

**为何需要分词 / 简单策略的缺陷：**
- **按词分词**：词表爆炸 + **未登录词 (OOV)**（新词无法处理）+ 语义关联缺失（look/looks/looking 三个独立词元）
- **按字符分词**：词表小无 OOV，但单字符大多无语义，学习效率低

**子词分词 (Subword Tokenization)**：兼顾词表大小与语义。常见词保留完整词元，生僻词拆成有意义的子词片段（如 Tokenization → Token + ization）。

**字节对编码 (BPE)**（GPT 系列采用，最主流）：
1. 初始化词表 = 所有基本字符
2. 统计相邻词元对频率，合并最高频的一对，加入词表
3. 重复直到词表达预设大小（贪心合并过程）

> 💡 例：语料 `{hug,pug,pun,bun}`，4 次合并依次：`ug→ug`、`ug</w>→ug</w>`、`un→un`、`un</w>→un</w>`。未见过的 "bug" 可切成 `['b','ug']`。

**后续衍生算法：**
- **WordPiece**（Google BERT）：合并标准非"最高频率"而是"最大化提升语言模型概率"（优先合并让语料更"通顺"的词对）
- **SentencePiece**（Llama 系列）：把空格当普通字符（下划线 `_`），分词/解码完全可逆、语言无关

**分词器对开发者的3个实际影响：**
1. **上下文窗口限制**：窗口按 Token 数算（非字符/词），中英文同段话 token 数差异大，精确管理输入长度是长时记忆智能体基础
2. **API 成本**：多数按 Token 计费，了解分词方式才能预估成本
3. **模型异常表现**：如 `2+2`（无空格）可能被分词器当新词元导致算错；首字母大小写不同也可能切成不同 token。设计提示和解析输出时要考虑

### 2.3 调用开源大语言模型（本地部署）

API 方式快但非唯一。对敏感数据/离线/控成本场景，需本地部署。

- 工具：**Hugging Face Transformers**，标准化加载数万预训练模型
- 推荐入门模型：`Qwen/Qwen1.5-0.5B-Chat`（约5亿参数，阿里达摩院开源，小巧性能好）
- 核心流程：
  1. `AutoModelForCausalLM` + `AutoTokenizer` 自动加载匹配的模型与分词器
  2. `tokenizer.apply_chat_template` 格式化对话（遵循模型特定模板，system/user 角色）
  3. `model.generate(input_ids, max_new_tokens=512)` 生成 Token ID
  4. `tokenizer.batch_decode` 把 Token ID 解码回人类文本

### 2.4 模型的选择

选型非简单"越大越强"，而是**性能/成本/速度/部署方式的权衡**。

**关键考量维度：**
1. **性能与能力**：不同模型擅长不同任务（推理/代码 vs 创作/翻译），参考基准榜（如 LMSys Chatbot Arena）
2. **成本**：闭源按 Token 计费；开源看本地硬件（GPU/内存）+运维
3. **速度（延迟）**：实时交互（客服/游戏NPC）要求响应快，轻量或优化模型更优
4. **上下文窗口**：长文档/长对话记忆需大窗口（128K+）
5. **部署方式**：API 便捷但数据出第三方；本地部署保隐私可控但要求高
6. **生态与工具链**：社区成熟度（LangChain/LlamaIndex/Transformers 兼容性）
7. **可微调性与定制化**：特定领域任务需微调能力，开源更灵活
8. **安全性与伦理**：偏见/毒性/幻觉表现，面向公众应用很关键

**闭源模型概览：**
- **OpenAI GPT 系列**：GPT-3 开时代 → ChatGPT（RLHF 对齐）→ GPT-4（多模态）→ GPT-5（多模态+通用智能新高点，实时语音出色）
- **Google Gemini 系列**：原生多模态，超长上下文；Gemini 2.5 Pro/Flash（后者快+省成本）
- **Anthropic Claude 系列**：重 AI 安全，长文档/减少有害输出/遵循指令可靠，企业级受青睐
- **国内闭源**：文心一言、混元、盘古、星火、Moonshot 等，中文优势+赋能本土产业

**开源模型概览：**
- **Meta Llama 系列**：开源里程碑，Llama 4 首批 MoE（仅激活任务相关部分提效）；Scout（1000万token窗口/长文档）、Maverick（多模态/编码推理）、Behemoth（最强大）
- **Mistral AI**："小尺寸高性能"，Mistral Medium 3.1 原生多模态 + 语调适配层
- **国内开源**：通义千问（Qwen）、清华智谱 ChatGLM，中文能力强+社区活跃

> 闭源 = 开箱即用；开源 = 随心定制。理解两派是智能体技术选型第一步。

## 三、大语言模型的缩放法则与局限性

### 3.1 缩放法则（Scaling Laws）

- 模型性能与**参数量、数据量、计算量**三者呈可预测的**幂律关系**（对数-对数坐标下平滑直线）
- 只要持续按比例增加三要素，性能就平滑提升，无明显瓶颈 → "在资源允许内尽量扩大规模和数据量"
- **Chinchilla 定律**（DeepMind 2022）修正"越大越好"：给定算力下，参数量与数据量有**最优配比**——模型应更小、但用多得多的数据训练（700亿参数的 Chinchilla 用比 GPT-3 多4倍数据，性能反超），强调**数据效率**
- **能力的涌现**：模型规模达阈值后突现小模型没有的能力（**链式思考 CoT、指令遵循、多步推理、代码生成**等）→ 做复杂自主决策/规划需选足够大的模型

### 3.2 模型幻觉（Hallucination）

- 定义：生成内容与事实/输入/上下文矛盾，或编造不存在的事实/实体/事件。本质是过度自信地"编造"而非检索/推理
- 分类：
  - **事实性幻觉**：与现实世界事实不符
  - **忠实性幻觉**：摘要/翻译未忠实反映源文本
  - **内在幻觉**：生成内容与输入直接矛盾
- 产生原因：训练数据含错误/矛盾信息；自回归只是"预测下一个最可能的词"没有内置事实核查；复杂推理时逻辑链条出错
- 其他局限：**知识时效性不足**（知识停在训练数据收集时）、**训练数据偏见**
- **缓解方法**：
  - 数据层面：高质量清洗、引入事实知识、RLHF
  - 模型层面：新架构/让模型表达不确定性
  - 推理与生成层面：**RAG（检索增强生成，先检索外部知识库再生成）**、多步推理+自我检查/外部验证、**调用外部工具**（搜索引擎/计算器/代码解释器）

## 四、本章小结（核心收获）

1. **模型演进**：N-gram（统计）→ 神经网络+词嵌入（解决泛化）→ RNN/LSTM（解决固定窗口）→ Transformer（注意力、并行）→ Decoder-Only（预测下一个词）
2. **交互两件事**：**提示工程**（采样参数、少样本、CoT 等引导行为）+ **分词**（BPE 等理解输入处理）
3. **选型权衡**：性能/成本/速度/上下文/部署/生态/可微调/安全 8 维度；闭源开箱即用 vs 开源自由定制
4. **法则与局限**：缩放法则（幂律、Chinchilla 数据配比、能力涌现）；幻觉/知识过时/偏见，需靠 RAG、多步推理、外部工具缓解

> 🔗 从 LLM 基础到构建智能体：这章解决"模型如何工作/如何交互/如何选/有何局限"，直接支撑后续智能体经典范式的提示词设计、模型选型、规避幻觉。下一章转向实践——智能体经典范式构建。
