## 一、目标案例：智能旅行助手

用户任务："查询今天北京的天气，然后根据天气推荐一个合适的旅游景点。"

智能体需展现：① 调用天气工具 → ② 拿到观察结果作为下一步依据 → ③ 调用景点推荐工具 → ④ 综合给出最终建议。

**四步演示了 Thought-Action-Observation 范式：任务分解、工具调用、上下文理解、结果合成。**

## 三、核心组件 1：指令模板（Prompt Engineering）

设计 `AGENT_SYSTEM_PROMPT`，作为 system_prompt 告诉 LLM 扮演什么角色、有哪些工具、怎么格式化输出——这是智能体的"说明书"。

```python
AGENT_SYSTEM_PROMPT = """
你是一个智能旅行助手。你的任务是分析用户的请求，并使用可用工具一步步地解决问题。

# 可用工具:
- `get_weather(city: str)`: 查询指定城市的实时天气。
- `get_attraction(city: str, weather: str)`: 根据城市和天气搜索推荐的旅游景点。

# 输出格式要求:
你的每次回复必须严格遵循以下格式，包含一对Thought和Action：

Thought: [你的思考过程和下一步计划]
Action: [你要执行的具体行动]

Action的格式必须是以下之一：
1. 调用工具：function_name(arg_name="arg_value")
2. 结束任务：Finish[最终答案]

# 重要提示:
- 每次只输出一对Thought-Action
- Action必须在同一行，不要换行
- 当收集到足够信息可以回答用户问题时，必须使用 Action: Finish[最终答案] 格式结束

请开始吧！
"""
```

关键点：**明确列出工具签名 + 规定 Thought/Action 格式 + 约定结束标志 Finish[...]**。

## 四、核心组件 2：两个工具函数

### 工具 1：查询真实天气（wttr.in 免费 API）
```python
import requests

def get_weather(city: str) -> str:
    """通过调用 wttr.in API 查询真实的天气信息。"""
    url = f"https://wttr.in/{city}?format=j1"   # 请求 JSON 格式
    try:
        response = requests.get(url)
        response.raise_for_status()
        data = response.json()
        current_condition = data['current_condition'][0]
        weather_desc = current_condition['weatherDesc'][0]['value']
        temp_c = current_condition['temp_C']
        return f"{city}当前天气:{weather_desc}，气温{temp_c}摄氏度"
    except requests.exceptions.RequestException as e:
        return f"错误:查询天气时遇到网络问题 - {e}"
    except (KeyError, IndexError) as e:
        return f"错误:解析天气数据失败，可能是城市名称无效 - {e}"
```

### 工具 2：搜索推荐景点（Tavily Search）
```python
import os
from tavily import TavilyClient

def get_attraction(city: str, weather: str) -> str:
    """根据城市和天气，使用Tavily Search API搜索并返回优化后的景点推荐。"""
    api_key = os.environ.get("TAVILY_API_KEY")
    if not api_key:
        return "错误:未配置TAVILY_API_KEY环境变量。"
    tavily = TavilyClient(api_key=api_key)
    query = f"'{city}' 在'{weather}'天气下最值得去的旅游景点推荐及理由"
    try:
        response = tavily.search(query=query, search_depth="basic", include_answer=True)
        if response.get("answer"):          # answer 是基于所有搜索结果的总结性回答
            return response["answer"]
        formatted_results = []
        for result in response.get("results", []):
            formatted_results.append(f"- {result['title']}: {result['content']}")
        if not formatted_results:
            return "抱歉，没有找到相关的旅游景点推荐。"
        return "根据搜索，为您找到以下信息:\n" + "\n".join(formatted_results)
    except Exception as e:
        return f"错误:执行Tavily搜索时出现问题 - {e}"
```

### 工具注册表（供主循环调用）
```python
available_tools = {
    "get_weather": get_weather,
    "get_attraction": get_attraction,
}
```

## 五、核心组件 3：通用 LLM 客户端

许多 LLM 服务（OpenAI、Azure、Ollama、vLLM）都遵循 OpenAI API 接口规范。实现一个通用 `OpenAICompatibleClient` 可对接任意兼容接口的 LLM：

```python
from openai import OpenAI

class OpenAICompatibleClient:
    """一个用于调用任何兼容OpenAI接口的LLM服务的客户端。"""
    def __init__(self, model: str, api_key: str, base_url: str):
        self.model = model
        self.client = OpenAI(api_key=api_key, base_url=base_url)

    def generate(self, prompt: str, system_prompt: str) -> str:
        """调用LLM API来生成回应。"""
        print("正在调用大语言模型...")
        try:
            messages = [
                {'role': 'system', 'content': system_prompt},
                {'role': 'user', 'content': prompt}
            ]
            response = self.client.chat.completions.create(
                model=self.model, messages=messages, stream=False
            )
            answer = response.choices[0].message.content
            print("大语言模型响应成功。")
            return answer
        except Exception as e:
            print(f"调用LLM API时发生错误: {e}")
            return "错误:调用语言模型服务时出错。"
```

实例化需三要素：`API_KEY`、`BASE_URL`、`MODEL_ID`（取决于服务商）。

## 六、核心组件 4：执行行动循环（主循环）

```python
import re, os

# --- 1. 配置LLM客户端 ---
API_KEY = "YOUR_API_KEY"
BASE_URL = "YOUR_BASE_URL"
MODEL_ID = "YOUR_MODEL_ID"
os.environ['TAVILY_API_KEY'] = "YOUR_TAVILY_API_KEY"

llm = OpenAICompatibleClient(model=MODEL_ID, api_key=API_KEY, base_url=BASE_URL)

# --- 2. 初始化 ---
user_prompt = "你好，请帮我查询一下今天北京的天气，然后根据天气推荐一个合适的旅游景点。"
prompt_history = [f"用户请求: {user_prompt}"]
print(f"用户输入: {user_prompt}\n" + "="*40)

# --- 3. 运行主循环 ---
for i in range(5):  # 最大循环次数
    print(f"--- 循环 {i+1} ---\n")
    full_prompt = "\n".join(prompt_history)

    # 3.2. 调用LLM进行思考
    llm_output = llm.generate(full_prompt, system_prompt=AGENT_SYSTEM_PROMPT)
    # 模型可能输出多余Thought-Action，截断到第一对
    match = re.search(r'(Thought:.*?Action:.*?)(?=\n\s*(?:Thought:|Action:|Observation:)|\Z)', llm_output, re.DOTALL)
    if match:
        truncated = match.group(1).strip()
        if truncated != llm_output.strip():
            llm_output = truncated
            print("已截断多余的 Thought-Action 对")
    print(f"模型输出:\n{llm_output}\n")
    prompt_history.append(llm_output)

    # 3.3. 解析并执行行动
    action_match = re.search(r"Action: (.*)", llm_output, re.DOTALL)
    if not action_match:
        observation = "错误: 未能解析到 Action 字段。请确保你的回复严格遵循 'Thought: ... Action: ...' 的格式。"
        observation_str = f"Observation: {observation}"
        print(f"{observation_str}\n" + "="*40)
        prompt_history.append(observation_str)
        continue
    action_str = action_match.group(1).strip()

    if action_str.startswith("Finish"):          # 结束
        final_answer = re.match(r"Finish\[(.*)\]", action_str).group(1)
        print(f"任务完成，最终答案: {final_answer}")
        break

    tool_name = re.search(r"(\w+)\(", action_str).group(1)   # 提取工具名
    args_str = re.search(r"\((.*)\)", action_str).group(1)   # 提取参数
    kwargs = dict(re.findall(r'(\w+)="([^"]*)"', args_str))  # 解析键值参数

    if tool_name in available_tools:
        observation = available_tools[tool_name](**kwargs)
    else:
        observation = f"错误:未定义的工具 '{tool_name}'"

    # 3.4. 记录观察结果，进入下一轮
    observation_str = f"Observation: {observation}"
    print(f"{observation_str}\n" + "="*40)
    prompt_history.append(observation_str)
```

**关键解析逻辑：**
- 用**正则**从 LLM 输出提取 `Action: xxx`、工具名 `(\w+)\(`、参数 `(\w+)="..."`。
- `Finish[...]` 触发结束，取出最终答案。
- 执行工具后把 `Observation:` 追加进 `prompt_history`，作为下一轮上下文。

## 七、运行案例分析（三轮循环）

```
用户输入: 你好，请帮我查询一下今天北京的天气，然后根据天气推荐一个合适的旅游景点。
--- 循环 1 ---
Thought: 首先需要获取北京今天的天气情况，之后再根据天气情况来推荐旅游景点。
Action: get_weather(city="北京")
Observation: 北京当前天气:Sunny，气温26摄氏度

--- 循环 2 ---
Thought: 现在已经知道了北京今天的天气是晴朗且温度适中，接下来可以基于这个信息来推荐一个适合的旅游景点了。
Action: get_attraction(city="北京", weather="Sunny")
Observation: 北京在晴天最值得去的旅游景点是颐和园，因其美丽的湖景和古建筑。另一个推荐是长城...

--- 循环 3 ---
Thought: 已经获得了两个适合晴天游览的景点建议，现在可以根据这些信息给用户提供满意的答复。
Action: Finish[今天北京的天气是晴朗的，气温26摄氏度...我推荐您去颐和园...或者长城...]
任务完成，最终答案: ...
```

> 这个案例集中演示了智能体四项基本能力：**任务分解、工具调用、上下文理解、结果合成**。通过循环迭代，把模糊用户意图转化为具体可执行步骤并达成目标。

## 八、智能体应用的协作模式（1.4）

基于智能体在任务中的角色与自主性程度，分两种模式：

### 模式 1：作为开发者工具（增强而非取代）
智能体深度集成进开发者工作流，自动化繁琐重复任务，让人专注创造性工作。主流 AI 编程工具：
| 工具 | 特点 |
|------|------|
| **GitHub Copilot** | 深度集成 VS Code，代码自动补全见长，近年扩展 Copilot Chat 对话式编程 |
| **Claude Code** | Anthropic 出品，终端内自然语言驱动编码，理解完整代码库，支持 headless 自动化 |
| **Trae** | 新兴 AI 编程工具，轻量快速，适合频繁迭代/快速原型 |
| **Cursor** | **AI 原生代码编辑器**（不是插件），设计之初即以 AI 交互为核心，懂整个代码库上下文 |

> 趋势：AI 正深度融入软件开发全生命周期，重塑工程效率边界。

### 模式 2：作为自主协作者（目标-委托）
把高层级目标**委托**给智能体，它像真正项目成员一样独立规划、推理、执行、反思直到交付。关系从"命令-执行"演变为"目标-委托"。

主流框架：从早期 BabyAGI、AutoGPT → 如今 CrewAI、AutoGen、MetaGPT、LangGraph 等。

## 九、核心要点速记

- **一个可跑的智能体 = 提示词模板 + 工具函数注册表 + 通用 LLM 客户端 + 主循环。**
- **提示工程**是灵魂：明确角色、列出工具签名、规定 Thought/Action 格式、约定 Finish 结束。
- **工具即能力**：把外部功能（天气/搜索 API）封装成函数，注册进 `available_tools` 字典。
- **通用客户端**：多数 LLM 服务兼容 OpenAI 接口，一个 `OpenAICompatibleClient` 通吃。
- **主循环**：拼接历史 → LLM 生成 → 正则解析 Action → 执行工具 → 追加 Observation → 下一轮。
- **结束条件**：`Finish[答案]` 或达到最大循环次数。
- **协作模式**：开发者工具（Copilot/Claude Code/Cursor，人机协同）vs 自主协作者（CrewAI/AutoGen/MetaGPT/LangGraph，目标委托）。
